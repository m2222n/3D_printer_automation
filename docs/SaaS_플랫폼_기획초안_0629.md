# 3D 프린팅 SaaS 플랫폼 — 기획 초안 (대표님 검토용)

> **작성**: 2026-06-29 (월) · 정태민
> **목적**: 대표님 6/18 지시(현 시스템을 앞·뒤로 확장해 **타 기업에 판매 가능한 제품**으로) 의 3축 기획 1차 초안.
> **성격**: **비전 + 로드맵 중심**. 코드 착수 전 방향 합의용. 화면 와이어프레임·DB 스키마 등 상세 설계는 방향 확정 후 별도 진행.
> **개발 방식**: 바이브 코딩 (5/6 방식 — 명세 먼저 → 대표님 align → 개발)

---

## 0. 한 장 요약 (먼저 읽으실 부분)

**우리가 이미 가진 것** = 3D프린터 실시간 모니터링 + 로봇 작업지시 (= 작은 MES). 이 "공정 실행 엔진"의 **앞단과 뒷단을 붙여** 완결된 제품으로 만든다.

```
   [① 앞단 — 신규]          [현재 — 보유]              [② 뒷단 — 신규]      [③ 경영계층 — 신규]
  고객 셀프주문 사이트   →   공정 실행 (프린터+로봇)  →  후공정 카운팅 모니터  +   ERP (자재 재고·발주)
  파일→견적→결제→투입         (현 웹 플랫폼/MES)          "몇 개 중 몇 개째"       레진·필라멘트 입출고
        │
        └─ ⭐ 이 전체를 멀티테넌트로 = 타 기업에 판매하는 제품
```

**왜 우리가 유리한가**: 경쟁사(온라인 출력 대행)는 주문 사이트만 있고 **현장 자동화가 없다**. 우리는 현장 자동화(프린터 제어·로봇)를 이미 보유 → "주문이 들어오면 **사람 손 거의 없이** 출력 큐에 자동 투입되고 후공정까지 카운팅되는" 시스템은 우리만의 차별점.

**1순위 제안**: **① 고객 셀프주문 홈페이지** 부터. (매출 직결 + 제품화 시장성 명확 + 견적·알림 자산을 이미 일부 보유해 가장 빠르게 데모 가능)

**핵심 일정 통찰**: 코딩보다 **행정 심사(PG 가맹, 카카오 알림톡 채널/템플릿 심사)가 더 오래 걸린다**(각 1~2주). → 방향 확정 즉시 **심사 신청부터** 걸고, 그 사이 개발.

## 1. 배경 — 현재 시스템과 표준 용어 (대표님 6/1 프레임 정합)

| 우리가 하는 일 | 표준 제조 용어 | 이번 확장에서의 위치 |
|---|---|---|
| 프린터 출력→세척→경화 (전공정) + 로봇 이송 (후공정) | 제조 공정 (SLA 적층) | 그대로 |
| 웹 플랫폼이 공정 실시간 모니터링·작업지시·로봇 제어 | **MES** (현장 실행) | **이미 보유** = 확장의 중심 엔진 |
| 고객 주문 받는 사이트 | 상거래(주문) 계층 | **① 신규** |
| 후공정 작업 카운팅 + 로봇 통신 | MES 확장 | **② 신규** |
| 레진/필라멘트 자재 재고·발주 | **ERP** (경영/자재) | **③ 신규** |

→ 즉 세 축 모두 "남의 개념을 새로 배우는 것"이 아니라, **우리가 이미 하는 일의 앞뒤를 표준 계층으로 채우는 것**.

## 2. ① 앞단 — 고객 셀프주문 홈페이지 (1순위) ⭐

### 2-1. 고객 경험 흐름 (대표님 6/18 지시 6단계)

```
1. 파일 업로드 (STL/3MF) + 옵션 선택(재료·수량)
2. 자동 견적 산출 (모델 분석 → 가격 즉시 표시)
3. PG 결제
4. 결제 완료 → 모델 파일이 바로 작업 큐로 자동 투입 (= 우리가 "출력 시작" 누르던 것까지 자동)
5. 공정 완료 시 고객에게 알림 (카카오 알림톡 / SMS / 이메일)
6. 고객 픽업 (또는 향후 배송)
```

### 2-2. 기능 범위 (MVP → 확장)

| 단계 | 기능 | MVP 포함 |
|---|---|---|
| 주문 | 회원가입/로그인, 파일 업로드, 주문 내역 조회 | ✅ |
| 견적 | 부피·치수 기반 자동 견적 (재료별 단가) | ✅ |
| 결제 | PG 결제 (카드·간편결제) | ✅ |
| 큐 투입 | 결제 완료 → 작업 큐 자동 등록 → 관리자 확인 후/자동 출력 | ✅ (반자동부터) |
| 알림 | 주문 접수·출력 시작·완료 알림 | ✅ (SMS/이메일 먼저, 알림톡 병행) |
| 고급 | 견적 정밀화, 배송 연동, 대량주문 협의, 도면 미리보기 3D 뷰어 | 차후 |

### 2-3. 자동 견적 — 어떻게 가격을 매기나

- **원천 데이터**: 업로드된 STL/3MF에서 **부피(cm³)·바운딩박스(치수)·watertight 여부**를 서버에서 추출.
- **방식**: `trimesh`(Python 라이브러리) 로 부피·치수 즉시 산출 → 부피 기반 견적.
  - SLA(레진)는 FDM과 달리 **재료가 부피에 거의 비례** → 부피 기반 간이 견적의 정확도가 실무상 충분.
- **견적 공식(초안)**: `견적 = max(최소주문금액, 부피 × 레진단가 × 서포트계수(1.1~1.3) + 후처리·세척 고정비) × (1 + 실패율 마진)`
  - 단가표·계수는 대표님과 실제 원가 기준으로 확정 필요 (이 문서에선 구조만 제안).
- **정밀 슬라이싱(PrusaSlicer/Cura CLI)** 은 출력시간·서포트까지 잡지만 엔진이 FDM 중심이라 SLA엔 오차+운영 복잡 → **2순위 옵션**으로 보류.

### 2-4. 외부 연동 (조사 결과)

| 영역 | 1순위 추천 | 이유 | 행정 리드타임 |
|---|---|---|---|
| 결제(PG) | **포트원(아임포트)** | 단일 SDK로 카드·카카오페이·네이버페이 일괄, PG 갈아타기 자유 | 사업자+통신판매업 신고+카드사 심사 (수일~2주) |
| 알림 | **솔라피(Solapi)** | 알림톡·SMS·이메일 단일 API + 알림톡 실패 시 SMS 자동 폴백 | 알림톡 채널 심사 3~7일 + 템플릿 심사 2~3일 |
| 견적 | **trimesh** | pip 한 줄, FastAPI 직접 임포트, SLA 부피모델 적합 | 없음 (즉시) |

> ⚠️ **순서 전략**: PG·알림톡은 **심사가 코딩보다 오래 걸림**. 방향 확정 즉시 신청 → 그 사이 trimesh 견적 + SMS/이메일 알림으로 MVP 먼저 가동 → 심사 통과 시 실결제·알림톡 스위치 온.

### 2-5. ⭐ 멀티테넌트 (타 기업 판매) — 제품화 관점

- 대표님 핵심 = "이 시스템 자체를 다른 기업에도 판매".
- 설계 원칙: 처음부터 **업체(테넌트) 단위로 데이터 분리** + 단가표/브랜딩/프린터 구성을 **업체별 설정값**으로.
- MVP는 **우리 공장(1테넌트)으로 먼저 완성**해 검증 → 구조만 멀티테넌트 대비(데이터에 tenant_id 부여)해 두면 추후 분리 비용 최소화.
- 판매 형태(후보): 월 구독(SaaS) / 설치형 / 거래 수수료 — 사업모델은 대표님 결정 영역.

## 3. ② 뒷단 — 후공정 작업 카운팅 모니터링

- **현재**: 후공정 모니터링 전무 (대표님 지적).
- **목표 화면**: 공장 모니터에 **"어떤 파츠 / 어떤 가공 / 총 N개 중 M개째"** 실시간 표시.
- **로봇 연계**: 우리는 이미 **HCR 로봇 ↔ Modbus 통신 자산** 보유 → 동일 작업 몇 번째 수행 중인지 카운트를 로봇에서 받아옴.
  - 빈피킹/이송 로봇 진척과 직접 연결 (회사 본업 자산 재사용).
- **MVP**: 주문(①)에서 들어온 "총 수량" + 로봇/공정에서 올라오는 "완료 수량" 매칭 → 진행률 대시보드.
- **난이도**: 로봇 통신 규격은 이미 정의돼 있어, 카운팅 표시 UI + 집계 로직 위주. (①보다 의존성 적지만 매출 직결성은 낮음)

## 4. ③ ERP — 자재 재고관리 (레진/필라멘트)

- **참고**: 대표님 제공 영상 2건(브런치/LinkedIn) 핵심 = **"작은 단위로 세분화, 핵심 기능부터, 사람은 승인만 하는 자동화, 실시간 의사결정 데이터"**.
- **범위(작게 시작)**:
  - 자재 마스터: SLA 레진 / FDM 필라멘트 종류별
  - **입고**(구매 등록) / **사용량**(출력 시 차감) / **잔여량**
  - 잔여량 임계치 도달 시 **발주 알림** 자동 표시
- **자산 재사용**: 우리 시스템은 이미 Formlabs API로 **카트리지/탱크 레진 사용량·잔량**(`initial_volume_ml`, `volume_dispensed_ml`)을 읽고 있음 → **레진 사용량 자동 차감의 원천 데이터를 이미 보유**. ERP의 "사람은 승인만" 자동화에 직결.
- **MVP**: 자재 목록 + 입출고 기록 + 잔량 + 임계 알림. 회계/구매 전체로 확장은 차후.
- **난이도**: 범위가 가장 작고 내부용이라 리스크 낮음. 단 매출 직결성은 가장 낮음.

## 5. 기존 자산 재사용 표 (신규 개발량 최소화)

| 필요 기능 | 기존 자산 | 신규 개발 |
|---|---|---|
| 사용자 인증 | ✅ JWT 인증 시스템 보유 | 고객용 회원/권한 분리, 멀티테넌트 |
| 완료 알림 | ✅ `notification_service` (Email/Slack/푸시 추상화 구조 보유) | **카카오 알림톡 / SMS** sender 추가 |
| 견적 원천 데이터 | ✅ Formlabs API (부피·재료·시간·레이어) | **업로드 파일 사전 견적**(trimesh) |
| 자재 잔량 데이터 | ✅ Formlabs 카트리지/탱크 잔량 | ERP 입출고·임계 로직 |
| 공정 실행/작업 큐 | ✅ 현 웹 플랫폼(MES) + 작업지시 | 결제→큐 **자동 투입** 연결 |
| 로봇 통신 | ✅ HCR Modbus | 후공정 카운팅 집계 |
| 배포 인프라 | ✅ Cloudflare Tunnel + 서버 운영 중 | 고객용 도메인/보안 분리 |
| 결제 | ❌ 없음 | **PG(포트원)** 신규 |

→ **3축 모두 "0에서 시작"이 아니라 보유 자산 위에 올린다.** 특히 알림·견적·자재는 핵심 부품을 이미 갖고 있음.

## 6. 단계별 로드맵 (제안)

> 본업(빈피킹+KAIST)이 ~7/9까지이므로, SaaS는 **기획 확정 후 본격 착수 시점은 대표님과 협의**. 아래는 착수했을 때의 순서.

| 단계 | 내용 | 산출물 |
|---|---|---|
| **0. 기획 확정** (지금) | 본 문서 검토 → 3축 우선순위·범위·사업모델 합의 | 확정 기획 |
| **0.5 행정 선신청** (확정 즉시) | PG 가맹 신청 + 카카오 알림톡 채널/템플릿 신청 (심사 동시 진행) | 심사 접수 |
| **1. ① MVP — 주문~견적** | 파일 업로드 + trimesh 자동 견적 + 주문 내역 (결제 전까지) | 데모 가능한 주문 사이트 |
| **2. ① 결제~큐 투입** | PG 실결제 + 결제 완료 → 작업 큐 자동 등록 + SMS/이메일 알림 | E2E 주문 1건 자동 처리 |
| **3. ① 알림톡 + 다듬기** | 알림톡 스위치 온, 견적 단가 튜닝, 고객 UX | 운영 가능 수준 |
| **4. ② 후공정 카운팅** | 로봇/공정 완료 수량 집계 대시보드 | 공장 모니터 화면 |
| **5. ③ ERP 자재** | 레진/필라멘트 입출고·잔량·발주 알림 (Formlabs 잔량 자동 연계) | 자재 관리 화면 |
| **6. 멀티테넌트 제품화** | 업체별 데이터 분리·설정·브랜딩 → 판매형 | 타 기업 판매 버전 |

## 7. 대표님께 여쭐 결정사항 (6/29 논의용)

1. **3축 우선순위 확정** — 초안 제안은 ① → ② → ③. 동의하시는지?
2. **견적 단가 정책** — 레진 단가·서포트계수·최소주문금액·실패율 마진 = 실제 원가 기준 수치 필요.
3. **사업모델** — 멀티테넌트 판매 형태(월 구독 / 설치형 / 수수료)?
4. **착수 시점** — 본업(~7/9) 대비 SaaS 본격 개발 시작 시점.
5. **행정 선신청 승인** — PG 가맹·알림톡 채널 신청을 지금 걸어둘지 (사업자/통신판매업 신고 상태 확인 필요).
6. **결제 첫 대상** — 우리 공장 자체 주문(내부 검증)부터인지, 처음부터 외부 고객인지.
