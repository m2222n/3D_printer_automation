한 장 요약

우리가 이미 가진 것 = 프린터 실시간 모니터링 + 로봇 작업지시 (작은 MES). 이 "공정 실행 엔진"의 앞단과 뒷단을 붙여 완결된 제품으로 만든다.

① 앞단 · 신규 고객 셀프주문 파일 → 견적 → 결제 → 큐 자동투입
→
현재 · 보유 공정 실행 (MES) 프린터 제어 + 로봇
→
② 뒷단 · 신규 후공정 카운팅 "몇 개 중 몇 개째" + 로봇 통신
＋
③ 경영 · 신규 ERP 자재 레진·필라멘트 입출고·발주
⭐ 이 전체를 멀티테넌트로 = 타 기업에 판매하는 제품
왜 우리가 유리한가 경쟁사(온라인 출력 대행)는 주문 사이트만 있고 현장 자동화가 없다. 우리는 프린터 제어·로봇을 이미 보유 → "주문이 들어오면 사람 손 거의 없이 출력 큐에 자동 투입되고 후공정까지 카운팅되는" 시스템은 우리만의 차별점.

1순위 제안: ① 고객 셀프주문 홈페이지부터. (매출 직결 + 제품화 시장성 명확 + 견적·알림 자산을 일부 보유해 가장 빠르게 데모 가능)

핵심 일정 통찰 코딩보다 행정 심사(PG 가맹, 카카오 알림톡 채널·템플릿 심사)가 더 오래 걸린다 (각 1~2주). → 방향 확정 즉시 심사 신청부터 걸고, 그 사이 개발.
1

배경 — 현재 시스템과 표준 용어

세 축 모두 "남의 개념을 새로 배우는 것"이 아니라, 우리가 이미 하는 일의 앞뒤를 표준 계층으로 채우는 것.

우리가 하는 일표준 제조 용어이번 확장에서의 위치
출력→세척→경화 (전공정) + 로봇 이송 (후공정)제조 공정 (SLA 적층)그대로
웹 플랫폼이 실시간 모니터링·작업지시·로봇 제어MES (현장 실행)이미 보유 = 확장의 중심 엔진
고객 주문 받는 사이트상거래(주문) 계층① 신규
후공정 작업 카운팅 + 로봇 통신MES 확장② 신규
레진/필라멘트 자재 재고·발주ERP (경영/자재)③ 신규
2

① 앞단 — 고객 셀프주문 홈페이지 ⭐ 1순위

고객 경험 흐름 (6단계)

  1. 파일 업로드 (STL/3MF) + 옵션 선택 (재료·수량)
  2. 자동 견적 산출 (모델 분석 → 가격 즉시 표시)
  3. PG 결제
  4. 결제 완료 → 모델 파일이 바로 작업 큐로 자동 투입 (우리가 "출력 시작" 누르던 것까지 자동)
  5. 공정 완료 시 고객 알림 (카카오 알림톡 / SMS / 이메일)
  6. 고객 픽업 (향후 배송)

자동 견적 — 어떻게 가격을 매기나

업로드된 파일에서 부피·치수를 서버에서 추출(trimesh) → 부피 기반 견적. SLA(레진)는 FDM과 달리 재료가 부피에 거의 비례해 간이 견적의 정확도가 실무상 충분.

견적 공식 초안 견적 = max(최소주문금액, 부피 × 레진단가 × 서포트계수(1.1~1.3) + 후처리·세척 고정비) × (1 + 실패율 마진)
※ 단가·계수는 대표님과 실제 원가 기준으로 확정 필요 — 이 문서에선 구조만 제안.

외부 연동 (조사 결과)

영역1순위 추천이유행정 리드타임
결제 (PG)포트원 (아임포트)단일 SDK로 카드·간편결제 일괄, PG 갈아타기 자유사업자+통신판매업 신고+카드사 심사 (수일~2주)
알림솔라피 (Solapi)알림톡·SMS·이메일 단일 API + 알림톡 실패 시 SMS 자동 폴백채널 심사 3~7일 + 템플릿 심사 2~3일
견적trimeshpip 한 줄, 백엔드 직접 임포트, SLA 부피모델 적합없음 (즉시)

⭐ 멀티테넌트 (타 기업 판매) — 제품화 관점

  • 대표님 핵심 = "이 시스템 자체를 다른 기업에도 판매".
  • 설계 원칙: 처음부터 업체(테넌트) 단위 데이터 분리 + 단가표·브랜딩·프린터 구성을 업체별 설정값으로.
  • MVP는 우리 공장(1테넌트)으로 먼저 완성해 검증 → 구조만 멀티테넌트 대비.
  • 판매 형태 후보: 월 구독(SaaS) / 설치형 / 거래 수수료 — 사업모델은 대표님 결정 영역.
3

② 뒷단 — 후공정 작업 카운팅 모니터링

  • 현재: 후공정 모니터링 전무.
  • 목표 화면: 공장 모니터에 "어떤 파츠 / 어떤 가공 / 총 N개 중 M개째" 실시간 표시.
  • 로봇 연계: 우리는 이미 HCR 로봇 ↔ Modbus 통신 자산 보유 → 동일 작업 몇 번째인지 카운트. 빈피킹/이송 로봇 진척과 직결.
  • MVP: 주문(①)의 "총 수량" + 공정에서 올라오는 "완료 수량" 매칭 → 진행률 대시보드.
  • 로봇 통신 규격이 이미 정의돼 있어 카운팅 UI + 집계 로직 위주. (①보다 의존성 적으나 매출 직결성은 낮음)
4

③ ERP — 자재 재고관리 (레진/필라멘트)

참고 영상 핵심(대표님 제공): "작은 단위로 세분화, 핵심 기능부터, 사람은 승인만 하는 자동화, 실시간 의사결정 데이터".

  • 범위(작게 시작): 자재 마스터(레진/필라멘트) · 입고 · 사용량(출력 시 차감) · 잔여량 · 임계 도달 시 발주 알림.
  • 자산 재사용: 우리 시스템은 이미 Formlabs API로 카트리지·탱크 레진 사용량·잔량을 읽고 있음 → 사용량 자동 차감의 원천 데이터를 이미 보유. "사람은 승인만" 자동화에 직결.
  • MVP: 자재 목록 + 입출고 기록 + 잔량 + 임계 알림. 회계/구매 전체 확장은 차후.
  • 범위가 가장 작고 내부용이라 리스크 낮음. 단 매출 직결성은 가장 낮음.
5

단계별 로드맵 (제안)

본업(빈피킹+KAIST)이 ~7/9까지이므로 본격 착수 시점은 대표님과 협의. 아래는 착수했을 때의 순서.

단계내용산출물
0. 기획 확정 (지금)본 문서 검토 → 3축 우선순위·범위·사업모델 합의확정 기획
0.5 행정 선신청PG 가맹 + 알림톡 채널·템플릿 신청 (심사 동시 진행)심사 접수
1. ① 주문~견적파일 업로드 + trimesh 자동 견적 + 주문 내역데모 가능한 주문 사이트
2. ① 결제~큐 투입PG 실결제 + 결제 완료 → 큐 자동 등록 + SMS/이메일 알림E2E 주문 1건 자동 처리
3. ① 알림톡 + 다듬기알림톡 스위치 온, 견적 단가 튜닝, 고객 UX운영 가능 수준
4. ② 후공정 카운팅로봇/공정 완료 수량 집계 대시보드공장 모니터 화면
5. ③ ERP 자재레진/필라멘트 입출고·잔량·발주 알림 (Formlabs 잔량 자동 연계)자재 관리 화면
6. 멀티테넌트 제품화업체별 데이터 분리·설정·브랜딩 → 판매형타 기업 판매 버전
7

대표님께 여쭐 결정사항 (6/29 논의용)

  1. 3축 우선순위 확정 — 초안 제안은 ① → ② → ③. 동의하시는지?
  2. 견적 단가 정책 — 레진 단가·서포트계수·최소주문금액·실패율 마진 = 실제 원가 기준 수치 필요.
  3. 사업모델 — 멀티테넌트 판매 형태 (월 구독 / 설치형 / 수수료)?
  4. 착수 시점 — 본업(~7/9) 대비 SaaS 본격 개발 시작 시점.
  5. 행정 선신청 승인 — PG 가맹·알림톡 채널 신청을 지금 걸어둘지 (사업자/통신판매업 신고 상태 확인 필요).
  6. 결제 첫 대상 — 우리 공장 자체 주문(내부 검증)부터인지, 처음부터 외부 고객인지.
