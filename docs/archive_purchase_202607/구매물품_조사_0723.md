**→ 카메라 판단(다양하게)**:

- ⚠️ **발주 전 필수 확인**: reCamera Pro의 MQTT/ONVIF 공식 스펙 / N6의 Modbus TCP 지원 / 각 제품 국내 정품 유통.

## 3. 웹캠 (디스플레이 OCR) — 오토포커스 vs 수동 바리포컬

> 우리 교훈: OpenMV 저해상 OCR 29% 실패 → **4K + 초점 물리조절** 필요. 거리·각도가 상황마다 다름.

### ⭐⭐ 심화 광학 분석 = "4K 필요"는 절반만 맞았다 (중요 정정)
> OCR 최소 해상도 이론(Cognex/Tesseract): **글자 높이 30px가 실무 안전선**. 지배 변수 = 센서 MP가 아니라 **"글자 하나가 몇 px로 찍히나" = FOV ÷ 센서 세로픽셀**.

- **광학 역산**(가정: LCD 글자 5mm, 목표 30px):
  - OpenMV(세로 320px): 5cm FOV까지만 30px 유지 → 손바닥 LCD엔 이미 깨짐 = **29% 실패 = 진짜 해상도 벽** [계산]
  - MaixCAM(세로 1520px): 이론상 25cm FOV까지 30px 가능한데도 **52% 실패** → ⭐**원인은 해상도 아닌 "근접 초점 미스+화각 부적합"일 가능성 높음**([실측필요]=MaixCAM 실패 프레임이 흐림인지 작음인지 확인)
- ⭐⭐ **진짜 결핍 = "초점·화각 조절 가능한 렌즈"**. 저해상이라도 렌즈로 LCD를 화면 가득 채우면 글자가 커짐. → **정석 = 4K 센서 + 수동 바리포컬 렌즈로 LCD를 꽉 채우기**(센서 여유가 정렬오차 흡수, 렌즈가 글자 키움).
- **거리별 필요 초점거리**(IMX415, LCD 세로 100mm 꽉 채울 때) [계산]: WD 200mm→f 6.3mm / 300mm→9.4mm / 500mm→15.7mm / 1000mm→31.3mm. → **ELP 2.8~12mm 바리포컬이 WD 0.2~0.5m 커버**, 1m는 5~50mm 변형.
- ⚠️ **LCD 반사 대응(새 발견)**: **원형편광(CPL) 필터로 화면 글레어 제거**(단 각도 잘못 돌리면 화면 blackout) + **고정 노출/게인 잠금**(자동노출은 백라이트에 끌려가 글자 날아감) + 조명 정반사각 회피. 매크로 렌즈는 우리 거리(수십cm~1m)엔 불필요.

## 4. 네트워크 장비 — "그대로 vs 변동"

서식 = "컨트롤/네트워크 일식 5,000천원"(스위치·UPS·태블릿·케이블). 우리 환경 기준 변동 제안:

| 항목 | 우리 환경 고려 |
|------|----------------|
| **스위치** | ⭐ **PoE 스위치 격상 검토** — PoE 카메라(reCamera 등)면 전원+데이터 한 선. WiFi AP격리 반복 교훈상 유선 확대가 맞음. 단 N6 PoE는 별도 실드 필요 |
| **AP격리 대응** | ⚠️ VLAN/전용 AP로 카메라 트래픽 격리 검토 |
| UPS·태블릿·케이블 | 유지 |

**→ 판단**: 큰 틀 유지 + **유선/PoE 확대**가 우리 WiFi 사고 이력에 맞는 "변동". 정확 모델·수량은 카메라 대수 확정 후.
