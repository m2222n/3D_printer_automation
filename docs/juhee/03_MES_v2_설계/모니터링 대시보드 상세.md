# 조작 화면은 3종류뿐

`node.ui_kind` 가 정한다. **공정 타입이 아니라 화면 종류**다.

| `ui_kind` | 쓰는 공정 | 하는 일 |
| --- | --- | --- |
| `BATCH_SPLIT` | 부품 분리 | 랙 > 칸 > 배치(FIFO) → 파트별 수량 판정 → `Split` |
| `PART_JUDGE` | 서포트 제거 · **치수검사** | 대기 부품 하나씩 OK/NG → 다음 공정 |
| `MONITOR` | 프린터 · 세척기 · 경화기 · 빔피킹 | 관측 + 상태 수동 입력 |
| `TRANSPORT` | 반송 자원 | 🔄 지금은 **명령 카탈로그 + 기록**(W6 절단본). 반송 지시 · 큐는 P5 |

서포트제거와 치수검사가 **같은 컴포넌트**를 쓴다. 둘 다 "부품 하나씩 판정"이다.
치수검사는 측정값 입력란만 추가된다. 화면을 하나 덤 만들고, 새 공정이 생겨도 기존 화면 중 하나를 고르면 된다.

## `BATCH_SPLIT` — 부품 분리

작업자 동선 그대로 4단계. 각 단계가 끝나야 다음이 열린다.

1. **랙 선택** — 이 노드의 직전 MAIN 노드에서 파생. 랙이 하나면 자동 선택
2. **칸 선택** — 빈 칸도 보여준다 (선택 불가로)
3. **배치 대기열** — FIFO 순서. **1번만 열린다.** 2번 이후는 흐리게 (`v_retrievable`)
4. **파트넘버별 판정** → 배치 완료 → `Split`

🔴 **부품 ID 를 쓰지 않는다.** 부품 `unit` 은 분해되는 순간 태어난다.
그 전에는 배치의 `unit_content` 에 "PN-A-2026 × 8" 처럼 수량으로만 있고,
작업자가 손에 든 물건과 매칭할 방법도 없다. 사람 눈으로 구분 가능한 단위는 **파트넘버**다.

```
PN-A-2026   치과모델 A형        8개
            OK [ 8 ]   NG [ 0 ]

PN-B-1180   치과모델 B형        4개
            OK [ 4 ]   NG [ 0 ]
```

- 기본값 **전부 OK**. NG 만 눌러서 깎는다 — 대부분 전부 OK 이므로
- NG ≥ 1 이면 사유 선택이 나타난다. `OK + NG = 총 수량` 유지
- **파트넘버당 1줄.** 12개짜리를 12줄로 펼치지 않는다
- `Split.outputs` 에는 **OK 수량만**. NG 는 `part_scrap` 으로 `unit` 이 안 생긴다
- 분리 완료 → `Moved(group_id, SEP-01 → SUP-01)` — **묶음째 1건**

## `PART_JUDGE` — 서포트 제거 · 치수검사

여기서는 **부품 ID 를 써도 된다** — 이미 존재하는 개체다.
다만 물리 매칭은 여전히 파트넘버로 하므로 둘 다 보여준다.

- 대기 부품을 **파트넘버로 정렬** — 같은 모양끼리 붙어 있어야 손이 덜 간다
- 판정은 `judgement` 에. 자동을 사람이 뒤집으면 새 행이라 이력이 남는다
- 치수검사는 `part.attrs.tol_mm` 이 있으면 측정값 입력란을 띄운다 (`judgement.value` jsonb)
- 서포트 제거 → 경화기는 **작업자가 고른다.** 비었으면 즉시, 돌아가면 그 경화기 대기 큐
- 경화기 개수 하드코딩 금지 — 다음 MAIN 노드에서 받는다
- 치수검사 → 빔피킹 대기 랙은 OK 박스(12개)에 모은다. `Moved(unit_id, join_group=BOX-xxxx)`
- 일괄 `[남은 부품 전체 OK]` — 실무에서 가장 많이 쓸 버튼. 크게

# 관측

- KPI — 재공(배치/부품), 완료(배치/부품), **반송 대기 건수**, 납기 임박 주문
- 주문 보드 — `v_order_progress`. 납기까지 남은 시간과 진척률
- 빈 플레이트 수 — `v_plate_usage`. 프린터 앞단의 진짜 제약일 수 있다
- 판정 — `judgement`. 서포트제거 OK/NG 와 치수검사 측정값이 같은 테이블. 자동 판정을 사람이 뒤집으면 이력이 남는다
- 대기 큐 — `v_waiting_for`. 치수검사 대기 큐는 물리 큐가 아니라 **파생** — 경화가 끝난 부품이 사람이 넣지 않아도 나타난다
- 조작 이력 — `command_log`. 모드 전환·반출 지시·박스 마감 등
- 랙 — 칸별 미니 게이지 + 만재 칸 표시. 랙 상세는 칸별 대기열을 순서대로 — 1번에 "다음 반출", 2번 이후는 흐리게
- 반송 자원 부하 — 핵심 병목 지표
- 이벤트 로그 — `source` 표시 (카메라/로봇/사람/프린터API/시뮬). 어디가 아직 수동인가
- `SETTLING` 과 `DONE` 구분 필수 — "못 꺼냄" vs "안 옮겨감"

# 수동 조작 (M2m)

- **수동 = 또 하나의 어댑터.** `source='MANUAL'`, M3a·M4·M5 무변경
- 조작은 **상세 패널에만**. 화면에 조작 버튼이 한 세트만 존재
- 위험 2등급 분리 — 관측 입력(DB만) / 물리 동작(로봇 실동작, 확인 단계 필수)
- **반송 모드 `AUTO`↔`MANUAL` 배타적 인터록** — 레지스터 130 경쟁 방지
- 이벤트 소스는 **설비마다 개별 전환** (프린터=API, 세척·경화=수동)
- ~~가능한 조작 목록은 **서버가 제공** (`actions[]`)~~ 🔄 미구현. 지금은 `ui_kind` 가 버튼 세트를 정하고, 엔진 거부(409)와 W6 `warnings` 를 사유로 표시한다
- 효과 — 카메라·Modbus 연동이 늦어져도 실제 생산 데이터 축적

## 작업자 반출 (경화 구간)

경화 구간은 작업자가 손으로 옮긴다. 랙 상세의 **[반출]** 액션.

1. **칸 선택** — 대기열이 있는 칸만
2. **수량 선택** — FIFO 이므로 앞에서부터 연속으로만. **미리보기**로 무엇이 빠지고 당겨지는지
3. **목적지 선택** — 서버가 준 목록에서. 잔여 용량 표시. **장당 목적지를 따로**
4. **확정** — 무엇이 어디로 가는지 다시 보여주고 확정
- **라인 이탈 경로 필수** — `폐기` / `보류` / `재작업 대기`. 없으면 작업자가 기록 없이 빼버리고 DB와 현실이 어긋난다
- 작업자가 쓰는 화면 — 버튼을 크게, 다음 할 일을 명시, 터치면 최소 44px
