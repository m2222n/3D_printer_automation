# 왜 이 문서가 필요한가

신규 설계안(PostgreSQL)은 **기존 운영 시스템 두 개 옆에 새로 세우는 것**이다.

대체가 아니라 병존이라면 둘을 잇는 장치가 필요한데, 지금은 그게 없다.

이 페이지는 **무엇이 다른지**만 담는다. 실측 근거와 표는 상세 페이지에.

# 🔴 이어지지 않는 것 3가지

## 1. 식별자 다리가 없다 — 가장 큰 구멍

```
기존         Form4-CapableGecko  ·  target_printer=1  ·  wash_id
신규         PRT-01              ·  WSH-01
잇는 컬럼    없음
```

`node` 17컬럼 어디에도 **외부 식별자를 담을 자리가 없다.** `topology.yaml` 에도 프린터 시리얼이 없다.

⇒ Formlabs 어댑터가 "Form4-CapableGecko 출력 완료"를 줘도 **어느 `unit` 인지 이을 수 없다.**

**택1** — `node.external_ref` 계열 컬럼 / 별도 매핑 테이블 `node_external_id`

## 2. 신규로 가면 사라지는 데이터

가장 큰 것은 빈피킹 **게이트 판정**(`gate_verdict` · `gate_valid_ratio_pct` · `gate_n_dropped_by_size`)이다.

없으면 **배경을 부품으로 잡은 장면이 정상으로 보인다** — 8/7 설계원칙 ③ 이 이걸 막으려고 만든 것.

그 밖에 카메라 장비 건강 · 알림 읽음 상태 · 셀 운전/시뮬 모드. **프론트 화면 3개가 갈 곳을 잃는다.**

## 3. `print_command` 와 `unit` 이 같은 것을 두 번 센다

둘 다 "한 번의 출력 분량"을 추적한다. 병존시키면 같은 물건에 `cmd_id` 와 `unit_id` 두 개가 생기고,

어느 쪽이 진실인지 정하지 않으면 **5/29 JWT 사고와 같은 계열**(두 시스템이 서로 다른 상태를 믿음)이 된다.

# 부수 발견 2건

**🐛 `PostProcStage` 값 순서가 실제 진행 순서와 다르다.**

세척 → 경화 전환에서 `60 → 10` 으로 역행한다. 실행 코드가 값으로 순서를 판단하지 않아 지금 버그는 아니지만,

📌 **마이그레이션 시 이 값을 `step_order` 로 쓰면 공정 순서가 뒤집힌다.** `route` 의 MAIN 엣지로 잡을 것.

**FK 제약이 A·B 양쪽 모두 0건.** C 는 FK 22건을 건다 — 이관 시 고아 행에 INSERT 가 막힐 수 있다.

# 🔴 결정이 필요한 것

| # | 질문 | 안 정하면 |
| --- | --- | --- |
| 1 | **C 는 A·B 를 대체하나, 병존하나?** | 나머지 판단이 전부 흔들린다 |
| 2 | 병존이면 — 프린터 완료를 누가 먼저 알고 누구에게 알리나 | 두 DB 가 서로 다른 상태를 믿는다 |
| 3 | `print_command` ↔ `unit` 중 어느 쪽이 진실인가 | 같은 물건에 ID 두 개 |
| 4 | `node` 에 외부 식별자 컬럼을 넣나, 매핑 테이블을 두나 | 어댑터가 unit 을 못 찾는다 |
| 5 | 빈피킹 게이트 판정을 어디에 남기나 | 못 믿을 인식 결과가 정상으로 보인다 |
| 6 | 카메라 장비 상태 · 알림 · 셀 운전상태를 C 로 옮기나 | 프론트 화면 3개가 갈 곳을 잃는다 |

**1번이 먼저다.** 대체인지 병존인지에 따라 2~6번의 답이 달라진다.

## 🔴 기존 코드에서 나온 발견 2건

### M2b — 대상 파일이 폐기본이었다

`bin_picking/.../modbus_server.py` 머리에 폐기 선언(2026-07-30)이 있다.
정본은 `sequence_service/app/cell/modbus_protocol.py` 이고 **방향이 반대**다.

- 우리는 **마스터** — `ModbusTcpClient` 로 로봇에 직접 쓴다 (슬레이브 우려 불식)
- 완료 신호 = **레지스터 206** Robot Moved

🚨 **파생** — `CLAUDE.md` 의 Modbus 절이 폐기된 맵이다. 별건으로 정정 필요.

### M2a — vision 상태감시가 실질 미가동

디바이스는 `timestamp` 를 **float**, 스키마는 **str** 을 요구한다.
`except Exception` 이 `ValidationError` 를 삼켜 **실물 메시지가 전건 사라진다.**
시뮬레이터는 `isoformat()` 을 보내 통과하므로 **테스트로는 안 잡힌다.**

## 겹치지만 대체가 아닌 것

|  | 왜 대체가 아닌가 |

| **M3b** `sequence_service` | 이미 반송 제어를 하고 있다. 두 벌이면 판단하는 코드가 둘인데 로봇암은 한 대다.
**신규 금지 · 2단계 개조** — ① `Moved` 발행만(~10/31) → ② `route` 이관(10/31 이후) |

## 🔴 계획이 다루지 않는 것

최신 계획은 `print_command` ↔ `unit` 중복을 **M3b 절의 "제어 로직 중복"으로만** 다룬다.
**데이터 중복 — 같은 물건에 `cmd_id` 와 `unit_id` 두 개가 생기는 문제 — 는 다루지 않는다.**

DB 배치·기존 데이터 이관·식별자 다리도 서술이 없다 (계획의 결정 게이트 D2 가 공란).

⇒ **위 스키마 결정 1번과 같은 질문**이다. 두 조사가 독립적으로 같은 곳을 가리킨다.
