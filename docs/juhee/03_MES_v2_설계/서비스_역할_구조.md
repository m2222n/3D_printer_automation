# 서비스 역할 구조 — web-api · line_mes · sequence_service 한 장

> 2026-09-30 코드 실측 기준 (`juhee`). 설계 배경은 `docs/juhee/02_개발계획/20260914_coexistence_plan.md` §3 (로컬 문서).
> 가르는 축은 **프로토콜이 아니라 방향**이다 — 쓰는 쪽(제어) · 읽는 쪽(관측) · 보여주는 쪽(API).

## 1. 한눈에

```
                 브라우저 (frontend/ · 9탭)
                        │ HTTP · JWT
                        ▼
┌─────────────────────────────────────────────────────────────────┐
│ web-api/                  API 층 · FastAPI · 포트 8085           │
│  app/api, local, vision, binpick   v1 (기존 화면)                │
│  app/line/                         v2 /api/v2 18 라우트 (라인 MES) │
│  소유 DB: SQLite presets.db                                       │
└──────┬──────────────────────┬───────────────────────┬────────────┘
       │ 읽기·CMD 생성        │ StateEngine 호출       │ 발행 1줄 (Spawn · State)
       ▼                      ▼                       ▼
┌──────────────┐   ┌───────────────────────────────────────────────┐
│ MariaDB      │   │ line_mes/          관측 도메인 · 순수 파이썬 패키지 │
│ automation   │   │  contract.py       이벤트 4종 = 유일한 경계        │
│ (제어 진실)   │   │  state_engine.py   이벤트 → product_state · 채번   │
└──────▲───────┘   │  publish.py        논블로킹 발행기                  │
       │ 소유       │  topology.yaml · topo_sync.py · schema.sql · simulator │
       │           │  소유 DB: PostgreSQL (LINE_DSN)                      │
┌──────┴──────────┐└───────────────────────────────────────────────┘
│ sequence_service/│  제어 층 · 단일 컨트롤러 스레드                 ▲
│  app/cell/       │  Modbus 마스터(로봇) · PreForm · 시퀀스         │ 발행 1줄 (State DONE · Moved)
│  app/cell/line_events.py ──────────────────────────────────────────┘
└─────────────────┘
```

| 서비스 | 역할 한 줄 | 쓰는 것(소유) | 읽는 것 | 프로세스 |
| --- | --- | --- | --- | --- |
| **web-api/** | 브라우저가 보는 전부 — 인증 · v1 화면 API · v2 라인 MES API · 정적 파일 | SQLite `presets.db` (프리셋 · 작업 · 알림 · 비전 이벤트 · 빈피킹 장면) | MariaDB(CMD 목록) · PostgreSQL(뷰 24) · Formlabs 클라우드 · MQTT 브로커 | uvicorn 1개. 루트 `main.py` 가 띄운다 |
| **line_mes/** | 관측 도메인 — "제품이 지금 어디 있나"의 규칙과 스키마. HTTP 없음 · 상주 프로세스 없음 | PostgreSQL 스키마 전부 (`schema.sql` 18테이블 · 24뷰) | `topology.yaml` · `web-api/.env PRINTER_SERIAL_MAP` | 없음. 두 서비스가 `import` 하는 라이브러리(`pip install -e .`) |
| **sequence_service/** | 제어 — 프린터 출력 지시 · 로봇 반송 · 셀 상태. **로봇에 쓰는 유일한 자리** | MariaDB `automation` (`print_command` · `cell_state` · `automation_log`) | 로봇 Modbus 레지스터 · PreFormServer · `../web-api/.env` | 스레드 1개. 루트 `main.py` 가 web-api 와 함께 띄운다 |

## 2. 의존 방향 — 한 방향만

```
web-api ──▶ line_mes ◀── sequence_service
   │                          ▲
   └── 읽기 · CMD INSERT ──▶ MariaDB ◀── 소유 · 상태 전이
```

| 규칙 | 근거 |
| --- | --- |
| `line_mes/` 는 **아무것도 import 하지 않는다** (표준 라이브러리 · psycopg · yaml 만) | 두 서비스가 둘 다 `app` 패키지라 어느 쪽에도 못 넣어 루트 패키지로 뺐다(9/23) |
| 두 서비스 → `line_mes` 는 **발행 한 줄**로만 닿는다 | web-api `app/line/publisher.py` · `app/local/line_publish.py` / sequence_service `app/cell/line_events.py` |
| 발행은 논블로킹 · 실패해도 제어를 막지 않는다 | `publish.py LinePublisher` = 큐 `put_nowait` + 데몬 스레드 · 큐가 차면 버린다 · `LINE_DSN` 비면 no-op |
| **위치를 바꾸는 것은 `Moved` 뿐**, 채번도 그때만 | 카메라·프린터 API 는 `State` 만 · 로봇 이동 완료(레지스터 206)가 `Moved` |
| 관측이 제어를 판정하지 않는다 | `state_engine` 거부(플레이트 소진 · 정원 초과)는 `source=SIM` 만 raise. 실물은 경고만 |
| 세 DB 병존 · 기존 DDL 0 변경 | SQLite · MariaDB 는 그대로. 다리는 `unit.cmd_id = print_command.cmd_id` 한 컬럼(FK 없음 · 한 방향 생성) |

## 4. 설정 · 기동

| 항목 | 값 |
| --- | --- |
| 기동 | 리포 루트 `python main.py` → web-api(uvicorn) + sequence_service 두 프로세스. 공장 PC 는 NSSM 서비스 |
| 공유 `.env` | `web-api/.env` 하나. sequence_service 는 `env_file=('.env', '../web-api/.env')` 로 같은 파일을 읽는다 |
| 라인 MES 스위치 | `LINE_DSN` — 비면 v2 라우트 503 `LINE_MES_OFF` · 발행 전부 no-op · FE 는 `/system/config.line_mes=false` 로 목업. **한 값으로 세 층이 함께 켜진다** |
| 활성 라인 | `LINE_ID` (`.env`) 와 `topology.yaml` 의 `active: true` 라인이 같아야 한다. 재배치 날 두 줄 함께 교체 |
| 프린터 시리얼 | `PRINTER_SERIAL_MAP` 하나 — web-api · sequence_service · `topo_sync`(→ `node.external_ref`) 가 다 여기서 읽는다 |
| 설치 | 루트 `pip install -r requirements.txt` (`-e .` 로 `line_mes` 포함). 배포는 `deploy.bat` |

| 위반 | 자리 | 왜 두는가 |
