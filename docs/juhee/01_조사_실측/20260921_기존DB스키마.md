# 기존 DB 스키마 — 실측 정리

**작성** 2026-09-21 · **방법** 파일을 읽고 살아있는 DB 를 덤프해서 셌다. 손으로 옮겨 적지 않았다.
**대상** 신규 `schema.sql`(P0 모니터링) **이전부터 돌고 있던 것** = web-api · sequence_service

> 🚨 **이 문서는 관찰 기록이지 정본이 아니다.** 기존 쪽에는 정본이 없다(§4).
> 신규 쪽 정본은 `schema.sql` 하나다.

# 1. 어디에 무엇이 있나

| DBMS | 파일 | 테이블 | 컬럼 | 정의 위치 |
| --- | --- | --- | --- | --- |
| **SQLite** | `web-api/presets.db` | **8** | **84** | SQLAlchemy 모델 3개 |
| **MariaDB 11.3** | 공장 PC `automation` | **4** | **34** | 모델 1개 + **raw DDL** |

🔴 **`.sql` 파일은 없다.** 리포에 있는 `.sql` 은 `schema.sql`(신규) 하나뿐이다.
⇒ 기존 스키마를 읽으려면 **파이썬 4개 파일과 DDL 2곳**을 봐야 한다.

**인덱스 18개** · 복합은 **1개**뿐이다 — `ix_binpick_scenes_module_created(module, created_at)`. 나머지는 전부 단일 컬럼.

(`gate_verdict` `gate_trusted` `gate_valid_ratio_pct` `gate_note` `gate_n_dropped_by_size`)
⇒ 8/13 에 *"JSON 안에 묻으면 조회·필터가 안 되고 그러면 아무도 안 본다"* 고 정한 그 설계가 그대로 있다.

🔴 **타입이 SQLite 기준으로 느슨하다** — `is_read` `is_online` 이 `INTEGER`(boolean 아님),
`settings` 는 `JSON` 이지만 SQLite 에서는 사실상 텍스트다. **PostgreSQL 로 옮기면 여기서 갈린다.**

# 4. 🚨 여기가 문제다 — "지금 DB 가 어떤 모양인가" 를 파일로 답할 수 없다

## 4-1. 같은 DDL 이 두 곳에 있다

`automation_log` · `automation_comm_config` 의 `CREATE TABLE IF NOT EXISTS` 가
**web-api 와 sequence_service 양쪽에** 있다:

| | 위치 |
| --- | --- |
| web-api | `app/local/automation_db.py:32` · `:52` |
| sequence_service | `app/cell/repository.py:108` · `:128` |

🔬 **문자열을 정규화해 비교했다 — 둘 다 현재는 완전히 동일하다.**
🚨 **그래서 지금은 안 터진다.** 한쪽만 고치는 날 갈라지고, **먼저 뜬 프로세스가 이긴다**
(`IF NOT EXISTS` 라 나중 것은 조용히 아무 일도 안 한다).

## 4-2. 마이그레이션이 코드 실행 시점에 일어난다

alembic 이 없다. 대신 기동할 때마다 `ALTER TABLE` 을 친다:

| 무엇 | 어디 |
| --- | --- |
| `print_command.washing_time` `curing_time` `use_yn` | `repository.py:40` `:46` `:52` (`ADD COLUMN IF NOT EXISTS`) |
| `cell_state.queue_state` `simul_mode` | `repository.py:92` `:98` |
| `cell_state.simul_mode` **(또 있다)** | `automation_db.py:411` — 🚨 이쪽은 `SHOW COLUMNS` 로 확인 후 `ADD COLUMN ... AFTER paused` |
| 데이터 보정 `UPDATE` 2건 | `repository.py` — `washing_time` 0 → 360, `use_yn` 빈값 → `'Y'` |

🚨🚨 **`simul_mode` 는 두 코드가 서로 다른 방법으로 추가한다**(`IF NOT EXISTS` vs `SHOW COLUMNS`).
⇒ ⭐ **결과 컬럼 순서가 어느 쪽이 먼저 돌았는지에 따라 달라진다**(한쪽만 `AFTER paused`).

⇒ 📌 **실제 스키마 = 모델 + DDL + ALTER 를 "몇 번, 어떤 순서로" 돌렸는가.**
정적 파일을 다 읽어도 답이 안 나온다.

## 4-3. 쓰지 않는 PostgreSQL 설정이 남아 있다

```
web-api/app/core/config.py:74   DATABASE_URL = "postgresql://localhost:5432/formlabs_db"
```
🔬 **전수 검색 결과 이 값을 읽는 코드가 0건이다**(테스트가 만지는 것은 `LOCAL_DATABASE_URL`).
⇒ 한때 PG 를 쓰려던 흔적이고 **지금은 죽은 설정**이다. 신규 v2 의 PG 위치를 정할 때 이걸 근거로 쓰면 안 된다.

# 5. 신규 `schema.sql` 과의 대비

| | 기존 | 신규 |
| --- | --- | --- |
| 정본 | 🔴 **없음** — 파이썬 4파일 + DDL 2곳 + ALTER | 🟢 `schema.sql` 한 파일 |
| 데이터 투입 | 코드가 기동 시 `ensure_*()` | `topology.yaml` → `topo_sync` |
| 마이그레이션 | 런타임 `ALTER TABLE` | 🟡 아직 없음(빈 DB 재생성) |
| "지금 몇 개인가" | 🔴 **DB 를 열어봐야 안다** | 🟢 빈 DB 에 올려서 센다 → **18 / 122 / 24** |
| DBMS | SQLite + MariaDB | PostgreSQL 14 |

🚨 **web-api 는 이미 DBMS 를 둘 본다.** v2 의 PG 를 web-api 에 붙이면 **셋**이 된다
(명세 §10-8 에 열린 채로 있다 — P5).

# 6. 🔴 확인하지 못한 것

| | 왜 |
| --- | --- |
| **공장 MariaDB 의 실제 모양** | 접근 권한이 없다. §3 은 **모델·DDL 에서 읽은 것**이고 실물 `SHOW CREATE TABLE` 이 아니다 |
| 운영 SQLite 의 행 수 | §2 는 리포의 **개발용** `presets.db` 다(presets 3 · print_jobs 5 · notification_events 3 · vision_cameras 4). 운영본은 더 많다 |
| 3개 서버 간 스키마 일치 | 6000 · 카카오 · 공장 PC 가 같은 모양인지 확인한 기록이 없다 — **ALTER 가 런타임이라 갈라질 수 있는 구조**다 |

⇒ 🥇 **공장에서 5분이면 닫히는 것** = `SHOW CREATE TABLE` 4개 + `PRAGMA table_info` 8개를 떠서 이 문서와 대조.
**그 전까지 §3 은 "코드가 의도한 모양"이지 "실제 모양"이 아니다.**
