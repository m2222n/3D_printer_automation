## 0. 한 줄 결론

**"많다"는 맞는데, 종류가 다섯이고 그중 넷은 서로 순서가 있다.** 순서를 지키면 매주 화면 하나가 진짜가 된다.

```
A  v2 라우터 18개 (읽기 12 · 쓰기 6)      ← 뷰를 FastAPI 로 감싸는 일. 데이터 계층은 끝나 있다
B  이벤트 생산자 5개                        ← 이것이 없으면 A 는 "빈 화면을 정확히 그리는" 일이다
C  기존 v1 API 수정 12건 (README TODO)      ← 대부분 "기록 한 줄 추가" · 두 건은 B 와 같은 일
D  인프라 8건                               ← 공장 PC 에 PostgreSQL 이 서기 전엔 전부 개발 DB 이야기다
E  FE 전환                                  ← 코드가 아니라 USE_MOCK 을 함수 하나씩 내리는 것 = 그것이 테스트
```

🥇 **가장 중요한 순서 하나** = **A 읽기 → B 생산자 → A 쓰기.** 읽기가 있어야 생산자가 낸 것이 보이고, 생산자가 있어야 쓰기 화면이 실물을 다룬다. 쓰기를 먼저 하면 검증할 데이터가 없다.

## 2. 순서 원칙 4개

1. **읽기 → 생산자 → 쓰기.** 쓰기의 검증은 "되읽기"다. 읽기가 없으면 쓰기를 검증할 수 없고, 생산자가 없으면 읽기가 빈 화면이다.
2. **기존 제어 루프는 한 줄만 건드린다** (`robot.py:204` 발행 1줄 · `printer.py` DONE 발행 1줄). 그것도 논블로킹으로. 병존 ②-2 — *"진짜 위험은 발행 실패가 아니라 블로킹"*.
3. **관측이 제어를 판정하지 않는다.** 엔진 게이트는 `source=SIM` 만 raise(9/22 반영). 실물에서 거부하면 unit 만 사라진다.
4. **한 화면씩 목업을 내리는 것이 테스트다.** pytest 를 새로 쌓지 않는다. `check.sh` 40건이 실 서버를 친다.

## 8. 매일 지키는 것

- 브랜치 = 묶음 단위(`feat/…` `fix/…` `refactor/…`) → `juhee` 에 `--no-ff` 병합 · **커밋·병합 메시지 = `[BE]`/`[FE]` + `type(scope): 설명`** (예 `[BE] feat(line-mes): …` · `[FE] merge(automation): …` · 양쪽이면 `[BE][FE]`)
- **한 번도 커밋된 적 없는 파일은 별도 확인 뒤에** 넣는다 — 묶음 커밋은 기존 추적 파일부터. 한 파일에 두 묶음이 섞이면 blob 을 만들어 부분 스테이징(9/23 `config.py` 전례)
- **커밋 전 보안 grep**(CLAUDE.md 4/24 사고) — README·명세·코드 주석에 IP·실명·자격증명 0건
- **명령은 실물 파일 하나로 리허설**(9/18 교훈 — 자체 테스트 통과 ≠ 실물 경로를 탔다)
- `USE_MOCK` 은 **함수 하나씩** 내리고 `check.sh` 를 돈다. 통과하면 다음 함수
- 훼손 시험(fault injection) 뒤엔 `__pycache__` 삭제(9/1 교훈)
