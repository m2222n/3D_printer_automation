- **ETag/304** (R1·R3·R5): `ETag = md5(max(product_state.updated_at) + 행수)`. `product_state` 로 결정되지 않는 응답(R2·R9·R10)엔 붙이지 않는다 — 틀린 304 가 최악. FE 5초 폴링 대부분이 304 로 끝난다.
- `topo_sync` 가 `transporters[].endpoint` 를 `attrs.endpoint` 로 적재 → R11 `protocol` 이 null 에서 `'modbus'` 로. 컬럼 추가 없음.

## 4. 설계 원칙 (오늘 코드가 지킨 것)

1. **관측은 제어를 막지 않는다** — 모든 발행은 논블로킹 · 자체 try · 실패는 warning 또는 error_message 로만. 엔진 거부도 실물 이벤트는 기록한다(`source=SIM` 만 raise).
2. **계산은 뷰가, 이름은 API 가** — 라우트 안에 비즈니스 계산 0. FE 가 화면마다 다르게 계산할 여지를 뷰가 닫는다.
3. **`product_state` 직접 UPDATE 0건** — 쓰기 6개 전부 contract 이벤트 → StateEngine.
4. **하드코딩 0** — 노드 매핑은 `topology.yaml external_ref`, EXIT 목적지는 route 엣지, 반송자원은 출발 노드 담당, protocol 은 yaml endpoint.
5. **거짓 성공을 답하지 않는다** — W6 는 송신 못 하면 `ok=false`, ETag 는 확정되는 응답에만, 개체 없는 State 는 `ok=false`.
6. **`LINE_DSN` 하나로 켜고 끈다** — 비면 v2 503 · 발행 no-op · FE 목업. 운영 PC 에 PG 를 올리기 전까지 아무것도 바뀌지 않는다.
