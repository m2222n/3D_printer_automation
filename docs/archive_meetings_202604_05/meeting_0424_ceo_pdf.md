## 2. 의사결정이 필요한 3대 안건

### 🔴 안건 1. 빈피킹 공정 컨셉 (가장 중요)

**왜 중요한가**: 공정 컨셉에 따라 알고리즘 난이도·카메라 배치·작업자 역할이 크게 달라집니다. 브라켓 설계와 개발 일정도 이 결정에 의존합니다.

#### 3가지 옵션 비교

| 옵션 | 배치 방식 | 알고리즘 | 현재 성능 | 상용화 시점 |
|------|----------|---------|----------|----------|
| **A** | 펼쳐서 (1단 배치) | SizeFilter + FPFH | **100%** (easy) | 즉시 가능 |
| **B** | 차곡차곡 (정돈된 트레이) | + OBB 방향 분석 | **100%** (medium) | 즉시 가능 |
| **C** | 무작위 힙 (진정한 빈피킹) | + Colored ICP + multi-view | **60%** (hard) | 5월 이후 |

#### 옵션별 작업자 개입

- **A**: 작업자가 부품을 격자/라인으로 펼쳐 배치 → 로봇이 순서대로 집기
- **B**: 작업자가 트레이/빈에 정돈 배치 → 로봇이 상단부터 집기
- **C**: 박스에 쏟아 놓음 → 로봇이 겹침 해석 후 집기

#### 태민 권장안

**초기 상용화는 A 또는 B 조합으로 시작, 기술 성숙 후 C 단계로 고도화**

- A/B는 현재 SW로 **즉시 데모 가능**, 실패 리스크 낮음
- C는 카메라 실데이터 확보 + Colored ICP 튜닝 필요 (5월 이후 현실적)
- 고객 데모·사업 보고는 A/B에서 먼저 성과 내고, R&D 단계로 C 접근

#### 대표님 확인 요청 사항

1. 사업 목표상 어느 단계까지 달성해야 하는지?
2. 고객 데모 시 작업자 개입(펼치기/정돈) 허용되는지?
3. 납기/일정상 우선순위는?

### 🔴 안건 2. Cloudflare Tunnel 적용 범위

**왜 중요한가**: Cloudflare 권한이 활성화되어 내일(4/24)까지 설정 마감 목표. 적용 범위에 따라 설비 안전성과 상용화 확장성이 달라집니다.

#### 3가지 범위 비교

| 범위 | 원격으로 할 수 있는 작업 | 네트워크 장애 시 리스크 | 복구성 |
|------|--------------------|-------------------|-------|
| **최소** (현장 합의) | 모니터링 + 이력 조회 | 없음 (로컬 동작 유지) | 실패해도 로컬 유지 |
| **중간** | + 프리셋/작업지시 전송 | 작업지시 실패 | UI만 가드 |
| **최대** (기존 방향) | + 로봇 직접 제어 | 로봇 오동작 가능 | 안전장치 필수 |

#### 현장 의견

- **예승 사원**: "설비제어는 무조건 로컬이 중요. 안 되면 로컬로 내려도 OK"
- **김주엽 파트장**: Cloud 이전 시 생략 단계·로봇 멈춤·잘못된 데이터 리스크 우려
- **Faridh님 (3/16)**: Cloudflare Tunnel + HTTPS 자동, 상용화 확장성 최적

#### 태민 권장안

**단기(4월): 최소 범위 → 중기(5월): 중간 범위**

- 최소 범위로 먼저 Tunnel 안정성 검증 (`factory.flickdone.com` → 공장 PC localhost:8085)
- 설비제어는 공장 PC 로컬만 허용, 카카오 VM/원격 UI에서는 Automation 탭 가드/숨김
- Basler 실연동 + 로봇 실제 피킹 안정화 후에 원격 작업지시 범위 확대

#### 대표님 확인 요청 사항

1. 상용화 시 현장 관리자가 원격에서 수행할 작업 범위는?
2. 로봇 제어 원격화를 고집할지, 로컬 원칙으로 갈지?
3. 내일까지 Tunnel 설정 완료 승인 여부?

### 🔴 안건 3. Basler 카메라 설치 방식 + 브라켓 제작

**왜 중요한가**: 카메라는 입고되었으나 장착하려면 브라켓이 필요합니다. 설치 방식과 브라켓 재질에 따라 제작 기간과 알고리즘 전략이 달라집니다.

#### 설치 방식 (현장 합의)

- **로봇 암 장착 (eye-in-hand)** — 파트장 권장, 대표님 4/10 지시와 정합
- **카메라 2대 동시 마운트**: Blaze-112 + ace2를 하나의 ㄱ자 브라켓에 나란히
- 장점: 인식 실패 시 로봇이 다른 각도에서 재촬영 가능 → 가시성 보완

#### 브라켓 제작 방식

| 옵션 | 장점 | 단점 | 비용/기간 |
|------|------|------|----------|
| **A. 3D 프린터 자체 가공** | 빠름, 무료, 수정 용이 | 하중·진동 리스크, 정밀도 한계 | 1~2일 |
| **B. 외부 금속 가공 외주** | 안정성·내구성·정밀도 | 비용, 수정 시 재제작 | 1주~ |

#### 카메라 하중 계산

- Blaze-112 약 500g + ace2 약 300g = **약 800g** (케이블 포함 1kg 예상)
- HCR-10L 가반하중 10kg 대비 여유 충분
- 3D 프린팅 프로토타입으로 시작해도 안전

#### 태민 권장안

**2단계 접근: (A) 3D 프린팅 프로토타입 → 실측 검증 → (B) 양산은 금속 가공**

- 1단계 (4/24~4/30): FDM 또는 SLA로 브라켓 출력 → 로봇 장착 → eye-in-hand 캘리브레이션
- 2단계 (5월): 실데이터 검증 결과 반영하여 금속 가공 발주

#### 대표님 확인 요청 사항

1. 브라켓 제작 예산 (외주 발주 시)?
2. 금속 가공은 재원텍에 맡길지, 다른 업체 알아볼지?
3. 3D 프린팅 재질 선택 (FDM ABS, SLA Tough 등)?
