## 1. v3가 풀어야 할 v2의 두 약점

| # | 약점 | v2 증거 | v3 해결 방향 |
|---|------|---------|-------------|
| 1 | **Part5 Recall 0.909 정체** | 5모델 전부 동일 = 모델 아닌 **데이터 문제** | Part5 단일 다각도 + 멀티 조합 보강 (50~80장), 클래스 균형 맞추기 |
| 2 | **도메인 갭 미검증** | valid도 train과 같은 5/15·18·20 환경 → mAP 0.99 = "외운 것" 의심 | **다른 환경 촬영(100~150장)** + 일부를 hold-out 평가셋으로 분리 |

추가 정리 과제:
- **Part6/7 라벨 잔존** — v2 valid 80장 중 7장 corrupt skip 원인. v3 데이터셋 빌드 시 Part6/7 라벨 파일 완전 제거 (또는 7클래스 통합 결정)
- **라벨 일관성** — Part2/Part3 헷갈림 케이스(v1 약점 원인) → 촬영 전 라벨링 가이드 한 장

## 2. 클래스 구성 결정 — 5클래스 유지 vs 7클래스 통합

v2는 데이터셋엔 7클래스(Part1~7) 있었으나 **학습은 5클래스**(Part6/7 train/valid 0장이라 nc=5로 학습). v3에서 정한다:

| 옵션 | 내용 | 장단점 |
|------|------|--------|
| **A. 7클래스 통합 (권장)** | Part6/7도 멀티 조합으로 충분히 촬영 → nc=7 정식 학습 | 한솔 실 부품군 전체 커버. 단 Part6/7 각 80~120장 필요 |
| B. 5클래스 유지 | Part6/7 보류, 5클래스 도메인 일반화에 집중 | 빠르지만 미완성 (한솔 부품 7종) |

→ **5/29 촬영에서 Part6/7 멀티 조합을 충분히 확보할 수 있으면 A(7클래스), 아니면 B로 v3 먼저 내고 v4에서 7클래스**. 5/29 현장에서 판단.

## 4. ⭐ 도메인 갭 평가셋 분리 전략 (가장 중요)

v2 우승 모델(yolov8n vs yolo11s)을 **정직하게** 가르려면, 학습에 한 번도 안 쓴 다른 환경 이미지가 필요하다 (5/27 재택에서 막혔던 바로 그것).

```
5/29 촬영 "다른 환경" 100~150장
        │
        ├─ 70% → v3 train/valid 에 투입 (도메인 일반화 학습)
        │
        └─ 30% (30~40장) → ❌ 학습 절대 미투입 → hold-out 평가셋
                            └─ v2 yolov8n.pt vs yolo11s.pt 둘 다 inference
                               → 진짜 mAP/Recall로 우승 모델 최종 선정
                               → v3 학습 후 같은 셋으로 v2 vs v3 도메인 갭 개선 측정
```

**규칙**: hold-out 평가셋은 Roboflow에 **별도 batch**(`20260529_holdout_*`)로 올리고 학습 버전에 포함하지 않는다. 누수 방지가 생명.

## 5. 모델 후보 — v3는 5개 → 2개로 집중

v2 교훈: 데이터 작아서 **큰 모델(8m/11m/11l) 과적합**. v3도 데이터 ~900장이면 작은 모델 유리.

| v3 학습 대상 | 이유 |
|-------------|------|
| **yolov8n** (6.3MB) | v2 mAP 1등 + 최소 크기 (IPC-510 배포 유리) |
| **yolo11s** (19.2MB) | v2 Recall 1등 + Part2 회복 최고 + 한솔 권고 모델 |

→ 두 후보만 학습해서 학습 시간 절약 + 도메인 갭 평가셋으로 최종 1개 확정.
(seg 모델 YOLOv11s-seg는 별도 트랙 — §7)

## 6. v3 실행 절차 (5/29 촬영 후 ~ 6월 초)

1. **5/29 촬영** — §3 분량, 메타데이터 스키마(`project_data_collection_long_term.md` §3-D) 준수, 파일명 `{YYYYMMDD}_partN_환경_시나리오_NNN`
2. **Roboflow 업로드** — batch 분리: `20260529_part5`, `20260529_domain`, `20260529_holdout`(평가셋), `20260529_multi*`
3. **Annotation** — Part5 + 도메인 갭 우선. 라벨 가이드 준수 (Part2/3 구분)
4. **데이터셋 빌드 v3** — Part6/7 라벨 정리 (7클래스 결정 따라 nc 확정). holdout batch는 **export 제외**
5. **AICA 학습** — `train_v3.sh` (v2 스크립트 복제, MODELS=2개) → AICA `/workspace/binpicking_yolo/dataset/v3/`
6. **도메인 갭 평가** — holdout 평가셋에 v2 두 모델 + v3 두 모델 inference → mAP/Recall 표 → 우승 확정
7. **best.pt 회수** — 6000 `runs/v3/` + Mac sync
8. **ONNX 변환** — 우승 모델 → ONNX (IPC-510 배포용, 사무실 GPU에서 속도 측정)
