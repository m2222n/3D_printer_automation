# 🥇 1순위 — 배경재 판정 (30분) 🚨 **본촬영의 게이트**

## 왜: 눈으로는 못 고른다. **가시광 차광 ≠ 850nm 흡수.**
검게 보여도 근적외선을 반사하면 배경이 depth로 채워져 **c3(F1 0.0000)** 가 된다.
⇒ 깔고 찍어서 **수치로** 판정하는 것이 유일한 방법.
🚨 **이걸 건너뛰고 30장을 찍으면 전부 버릴 수 있다.**

## 1-0. 스크립트 받기 (5분)

맥 터미널:
```bash
cd ~/3D_printer_automation && git pull
cp bin_picking/depth_track/scripts/blaze_capture_crosssession.py ~/Desktop/
cp bin_picking/tests/check_background_material.py ~/Desktop/
```
⚠️ `git pull`에서 충돌·"local changes"가 나면 **덮어쓰지 말 것** → scp로 파일 2개만 우회.

## 1-1. 카메라 네트워크 (1줄)

```bash
sudo python ~/3D_printer_automation/bin_picking/tests/setup_camera_net.py --apply
```
⭐ 날아가는 것은 카메라가 아니라 **맥 랜포트 IP**다(카메라는 Static). 이 한 줄이면 복구된다.

## 1-2. 🔴 배치 — 여기서 결과가 갈린다

- **차광 용지를 테이블에 깐다** → 그 위에 **공구상자**를 올린다 → 상자 안에 부품
- 🚨 **용지는 빈 자리를 통째로 덮어야 한다(66.5×68cm 이상)**
  인식 영역이 450mm에서 **823×464mm**라 상자(450×270)만으론 화면 절반이 맨 테이블이다
- 🚨 **종이는 말리고 주름진다** → 평평하게 눌러 고정. 주름은 depth에 무늬를 만든다
- ⚠️ **이음매가 생기면 depth에 줄무늬** → 한 장으로 덮는 것이 최선

## 1-3. 5~10장 찍고 판정

```bash
cd ~/Desktop && sudo python blaze_capture_crosssession.py \
  --out ~/Desktop/bg_test_0814 --target 10 --scale 2
```
촬영 중 화면에서 **DIST 게이지가 444~483mm**인지 확인(상자 깊이 120mm만큼 부품이 올라온다.
🚨 거리는 **상자 바닥이 아니라 부품 표면** 기준).

```bash
python ~/Desktop/check_background_material.py ~/Desktop/bg_test_0814 --with-baseline
```

### 판정 기준

| 결과 | 뜻 | 행동 |
|---|---|---|
| 🟢 **유효율 4~8%대** | c1(학습 조건) 재현 | ✅ **본촬영 GO** |
| 🟠 10~25% | 분포 안이지만 경계 | ⚠️ 용지를 더 넓게 덮고 재판정 |
| 🔴 25% 초과 | 배경이 depth로 채워짐 | 🚨 **용지가 850nm에 안 통함** → 아래 대응 |
| 🔴 부품 대역 <0.5% | 배경은 지웠는데 **부품이 안 잡힘** | 거리·자세 재조정 |

### 🔴 용지가 떨어지면 (25% 초과)

**본촬영을 강행하지 말 것.** 대신:
1. 용지를 **두 겹**으로 깔고 재판정(반사가 줄 수 있다)
2. 그래도 안 되면 → **무광 검정 시트지를 데이터와 함께 재요청**
   ⭐ 8/10에 사내 보유분으로 대체하며 취소된 건이라 **수치가 있으면 재요청 근거가 된다**
3. 🥈로 넘어가지 말고 **🥉 IPC로 순서를 바꾼다**(촬영은 자재 재확보 후)

# 🥈 2순위 — 본촬영 30~50장 (1~2h)

## 🚨 판정 통과했을 때만.

```bash
cd ~/Desktop && sudo python blaze_capture_crosssession.py \
  --out ~/Desktop/blaze_recapture_0814 --target 50 --scale 2
```

- `s` = 저장 / `스페이스` = 조건 그룹 변경(메모 입력) / `u` = 직전 취소 / `q` = 종료
- ⭐ **이어찍기 가능** — 중간에 끊겨도 같은 `--out`으로 다시 실행하면 이어진다

## 구성 (8/7 실패에서 나온 규모)

- ⭐ **최소 30장, 가능하면 50장 이상** — 8/7 실패 원인이 **7장이 87장의 8%뿐**이라
  분포를 못 움직인 것. 유의한 비중이 되어야 한다
- 부품을 상자에 **무작위로 쏟아 담고 매번 흔들어** 자세 변경
  (무작위 적재는 **안정 자세로 수렴** = 가장 얇은 면이 바닥에 닿는다)
- **겹침 60% / 펼침 40%**
- 🚨 **학습 27종 전부 유지** — 공정 대상 19종으로 줄이지 말 것
  (제외 4종도 카메라엔 보이므로 빼면 **다른 부품으로 오인**한다)

## 촬영 중 체크

- [ ] DIST **444~483mm** 안인가
- [ ] 부품이 **화면 중앙 2/3** 안인가 (`--center_crop '1/6,5/6'`에 잘린다)
- [ ] **상자 테두리가 크게 안 들어오는가** (c2 조건 = F1 0.0814)

## 찍고 나서 즉시

```bash

```
⚠️ **이 판정은 "학습 분포 안인가"까지만 답한다.**
**F1은 라벨링을 해야 안다** — 7/31에 라벨 없이 "폭락 재현 안 됨"이라 했다가 8/5에 뒤집힌 전례.
⭐ **"몇 개 찾았나"와 "맞게 찾았나"는 다른 질문이다.**

## 문제 대응

**A. 카메라가 안 열린다**
`sudo python bin_picking/tests/setup_camera_net.py --apply` → 그래도 안 되면
`arp -an | grep <MAC>`로 L2 확인. ⭐ **열거는 되는데 열기만 timeout이면 대역 불일치**
(카메라 IP 대역 = 꽂힌 랜포트 대역).

**B. DIST가 3000 근처로 뜬다** (실제 50cm인데)
→ `--raw-is-mm` 플래그. 저장 원본은 어느 쪽이든 raw라 안전.

**C. 판정 도구가 죽는다**
`--with-baseline` 없이 먼저 돌려볼 것(기준선 로드가 문제일 수 있음).
