## 판정

### ⚠️ "종류 F1 0.85는 실질 병목이 아니다"는 **성립하지 않는다**

7/28 격차 분석의 낙관적 가설(**"혼동이 전부 대칭쌍이라 파지점이 같으면 실질 병목이 아닐 수 있음"**)은 **부분적으로만 맞다**. 4쌍 중 **`r_guide_a` 1쌍만** 파지값이 완전히 같아 종류를 틀려도 무해하다. 나머지 3쌍은 벌림 폭이 달라 **오분류가 곧 잘못된 벌림**으로 이어진다.

### 심각도는 쌍마다 다르다 — 한 덩어리로 보면 안 된다

| 쌍 | width 차 | 위험 | 판단 |
|---|---|---|---|
| `07/09_guide_paper` | **20mm** (80↔60) | 🔴 **큼** | 69mm 부품을 60mm로 벌리면 **물리적으로 안 들어감**(끼임·충돌). 반대로 50mm 부품을 80mm로 벌리면 **헛집음** |
| `roll_cover l/r` | 5mm (40↔35) | 🟡 중간 | 28mm 부품을 35mm로 벌리면 여유 7mm — 파지 자체는 되나 중심이 흔들릴 수 있음 |
| `03/06_sol_block` | 2mm (40↔38) | 🟢 작음 | 여유 오차 범위. 실질 무해로 보임 |
| `r_guide_a l/r` | **0** | ✅ 없음 | 종류 오분류가 파지에 영향 없음 |

⚠️ 단 `07/09`와 `r_guide_a`는 **길이가 45~46mm씩 다르다**(163 vs 117.8 / 부피 1.5배). 벌림은 같아도 **집는 위치(무게중심)가 어긋나면** 긴 부품을 짧은 부품 중심으로 집어 기울 수 있다. `grasp_center_mm`이 4쌍 모두 `[0,0,0]`(부품 중심)이라 **부품 자체 좌표계 기준이면 문제없으나**, 오분류 시 **다른 부품의 중심을 쓰게 되는지**는 L4 자세추정 구현에 달려 있다 → `미확인`.

## 파생 결론 — 병합 실패의 의미가 명확해졌다

7/9 발표에서 `roll_cover` 1쌍만 정직 병합해 재학습한 결과가 **F1 0.669 < 27종 0.684**였다(`depth_track/README.md`). 이번 분석과 합치면:

- **병합은 애초에 옳은 처방이 아니었다.** `roll_cover`는 파지 벌림이 5mm 다르므로, 병합해 한 클래스로 만들면 **어느 쪽 벌림을 쓸지 알 수 없게 된다**. 지표는 올라갈 수 있어도 **로봇 동작은 오히려 불능**이 된다.
- 즉 병합으로 점수를 올리지 못한 것은 손실이 아니라, **로봇 관점에서 하면 안 되는 일이었음**을 보여준다.
- ⭐ **진짜 처방은 유형별로 갈린다**: `r_guide_a`(파지 동일)는 **병합해도 무해** / `07/09`(20mm 차)는 **반드시 구분해야 함 → RGB 융합 대상 1순위**.

## 실행 항목

1. 🔴 **`07/09_guide_paper` 구분 정확도를 별도로 측정** — 전체 F1 0.85가 아니라 **이 쌍의 per-class recall**이 실제 로봇 리스크 지표다. `diag_pairs.py`가 쌍별 혼동 횟수를 뽑으므로 저장된 eval 결과에 돌리면 됨(GPU 불필요, 단 test102 per-scene CSV 필요 → `확인 필요`).
2. 🟡 **RGB 융합 우선순위 재정렬** — 7/28까지는 "표면 패턴(유형 B)"이 융합 대상이었으나, **로봇 피해 기준으로는 `07/09`(치수차 20mm)가 1순위**.
3. 🟢 **`r_guide_a`는 병합 후보로 유지** — 파지 동일이므로 종류 구분에 자원을 쓸 필요 없음. 클래스 27→26 축소로 다른 부품 정확도에 여유를 줄 수 있음(⚠️ 단 7/9 실험처럼 F1이 오히려 내려갈 수 있어 재학습 검증 필요).
4. ⚠️ **`gripper_width_mm` 값 자체가 미검증** — `grasp_database.yaml:22-23`이 "STL bbox 기반 추정치, 카메라 입고+로봇 티칭 후 실측 교정 필요"라고 명시. 위 판정은 **추정치 간 비교**이며, 실제 그리퍼 사양(스트로크·분해능)이 확정되면 재평가해야 한다. 특히 2mm 차(`03/06`)는 그리퍼 반복정밀도 이하일 수 있음.
