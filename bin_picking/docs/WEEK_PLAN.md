## 🚨🚨 8/24 확인으로 전제가 또 하나 바뀌었다 — **RGB는 후처리로 못 끝낸다**

8/21에 *"RGB 실측 데이터가 0건"* 인 것까지는 잡았는데, **모델 쪽은 안 봤다.**
오늘 체크포인트를 직접 열어보니 더 큰 제약이 있었다.

```
T100_csblur_lr1e4_ep80/best.pt
  input_mode = zv
  backbone.stem.0.block.0.weight = (32, 2, 3, 3)   ← 입력 채널 2개로 물리적으로 박힘
```

| 확인한 것 | 결과 |
|---|---|
| 배포 모델 입력 채널 | **2채널**(정규화 depth + 유효 마스크) — 체크포인트에 박혀 있음 |
| 모델이 지원하는 입력 모드 | `z`(1) · `zv`(2) · `xyzv`(4) · `xyznv`(7) — **전부 depth 파생, RGB 모드 없음** |
| 8/18 90장 `.npy` | (480,848) uint16 = **depth 단독 2차원** |
| 8/18 90장 `.png` | depth 컬러맵 렌더(1696×960 = npy의 정확히 2배) — **카메라 컬러 아님** |

⇒ 🚨 **RGB를 붙이면 첫 conv의 shape이 바뀌어 기존 체크포인트를 못 읽는다 = 재학습 필수.**
8/21의 화이트리스트처럼 **후처리로 이득을 얻는 경로가 아니다.**

### ⭐ 그래서 오늘 판단 하나가 바뀐다 — **촬영을 2회차로 나눈다**

재학습이 필수면 **오늘 찍은 것은 학습셋**이 되고, 그것으로 성능을 재면
8/20에 밟을 뻔한 **train-on-test**를 그대로 반복하게 된다.

⇒ **오전/오후로 세션을 갈라 찍는다.** 중간에 카메라를 한 번 떼었다 다시 달면
"다른 날"에 가까워져 cross-session 성격이 살아난다.

| 세션 | 장수 | 용도 |
|---|---|---|
| **A (오전)** | 60장 | 🎓 **학습셋** |
| **B (오후, 재설치 후)** | 30장 | 🧪 **시험지** — 이걸로만 판정 |

🚨 **B는 학습에 절대 넣지 않는다.** 8/18 90장도 재학습 C의 학습 데이터라 시험지로 못 쓴다.
