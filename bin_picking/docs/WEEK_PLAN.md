## 🎯 왜 이 순서인가

**지금 = 조각마다 점수는 있는데 전체가 되는지 아무도 모른다.**
인식 0.5998 ✅ / 좌표 산출 ✅ / 소켓 801건 ✅ / 웹 전달 ✅ —
그런데 **"찍어서 로봇이 실제로 집는 것"은 0번** 해봤다.

⭐ **원칙 = "조용히 틀리지 말고 크게 실패하라"** ⇒ **가장 모르는 것을 가장 먼저 친다.**
🚨 hand-eye에 근본 문제가 있다면 **지금 알아야 한다.** 9월 말에 알면 손쓸 수 없다.

**🔴 지금 하지 않을 것**
- **RGB 융합** — 8/20 실측상 치명 23건 중 **표면패턴 후보는 4건(0.8%)**, 나머지 19건은
  **크기 차이**라 컬러가 못 푼다. 재택 2일 소모. **데이터는 이미 확보했으니 언제든 가능**
- **F1 추가 개선** — 이득 소진(추가촬영 +0.03 / TTA −0.070 / 임계값 0.10 포화)
- **eye-in-hand 전환** — 고정 거치로 먼저 성공시킨 뒤

## 🏠 8/26 (화, 재택) — IPC가 1순위

🚨 **IPC 이전이 hand-eye의 선행조건이다.** 로봇은 지금 **공장 PC**에 붙어 있는데
배포 대상은 **IPC-510**이다. 공장 PC에서 먼저 하면 **나중에 IPC에서 다시 해야 한다.**

| 시간 | 주 작업 | 병행 |
|---|---|---|
| **오전** | 🥇 **IPC 원격 세팅**(Tailscale) — pylon 설치 · E2E 러너 이식 · **npy로 6000과 결과 대조** | |
| **오후** | 🥈 **hand-eye 설계** — 3점법 절차서 + 좌표 변환 코드 | 🏷️ **라벨링 세션 B 30장** |

⭐ IPC를 오전에 두는 이유 = **막히면 하루가 필요**하다. 라벨링은 언제든 되지만 IPC는 금요일 전에 끝나야 한다.
⭐ **라벨링은 B(시험지) 30장 먼저** — 끝나면 **현재 모델을 한 번도 안 본 데이터로 평가**할 수 있어
**"새 시험지에서 F1 몇"** 이라는 보고 가능한 숫자가 나온다(RGB 없이도).

## 📌 라벨링 메모

- 🚨 **depth만 라벨링한다.** RGB는 별도 라벨이 아니라 **나중에 채널로 붙는 것**이고,
  해상도가 달라(848×480 vs 2448×2048) 두 벌 만들면 어긋난다.
  RGB 라벨이 필요해지면 **정합으로 변환**한다(사람이 다시 그리지 않는다).
- ⭐ **RGB는 보조 참고용으로 띄워둔다** — depth에서 뭉개진 부품이 뭔지 확인할 때 유용하다.
