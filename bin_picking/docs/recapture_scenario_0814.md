## 1.5 🔌 촬영 장비 = **맥** (IPC 아님) + 케이블 정리

### 왜 맥인가

| | 맥 | IPC-510 |
|---|---|---|
| pylon(카메라 드라이버) | ✅ 설치됨 | 🔴 **없음**(8/14엔 추론 환경만 깔았다) |
| 촬영 스크립트 | ✅ 검증됨 | 🔴 미검증 |
| 카메라 네트워크 | ✅ `setup_camera_net.py` | 🔴 미설정 |

⭐⭐ **더 중요한 이유** = **학습 세션 200장을 전부 맥으로 찍었다.**
지금 목표가 **그 조건을 재현하는 것**인데 촬영 장비를 바꾸면 **변수가 하나 더 늘어난다.**

🚨 8/10 체크리스트 원칙 그대로다:
> **물리 환경만 바꾸고 센서 설정은 전부 고정한다.** 같이 바꾸면 성능이 떨어졌을 때
> *"일반화 실패"* 인지 *"설정 불일치"* 인지 **구분이 안 된다**(7/6 LongRange 사고).

⇒ 카메라를 IPC에 물리는 것은 **운영 배포 단계**의 일이고, 그때 **오늘 데이터가 기준선**이 된다.

**카메라 네트워크 복구 (한 줄)**
```bash
sudo python ~/3D_printer_automation/bin_picking/tests/setup_camera_net.py --apply
```
⭐ 날아가는 것은 카메라가 아니라 **맥 랜포트 IP**다(카메라는 Static).

### 📷 **Blaze 단독** — ACE2(RGB)는 연결하지 않는다

- `depth_track` 모델은 **Blaze depth만 입력**으로 받는다. 학습 200장도 전부 depth였다
  ⇒ **ACE2를 켜도 이번 재학습에 쓰이지 않는다**
- ⭐ **변수를 줄이는 것이 오늘 목적**이다 — 두 카메라를 동시에 열면 GigE 대역·IP가 얽히고,
  7/28~7/31에 실제로 그것으로 여러 번 막혔다

⚠️ **다만 알아둘 것** = 나중에 **RGB 융합 D단계**로 가면
**depth와 RGB를 같은 시점에 찍은 쌍**이 필요하고, 그때는 **또 촬영해야 한다.**

🔵 **그래도 오늘 하지 않는 이유**:
① RGB 융합은 **이번 재학습이 실패했을 때의 다음 수**다
② 두 카메라 동시 촬영은 **오늘 처음 하는 일**이라 소요를 모른다
③ 오늘 목표(**21종 커버리지 확보**)가 더 급하다

⇒ ⭐ **Blaze 단독으로 확실히 끝내고, RGB 쌍은 필요해지면 그때 찍는다.**
**정합(extrinsic)은 7/31에 이미 검증**돼 있어 나중에 찍어도 그대로 쓸 수 있다.

### 🚨 케이블이 화면에 보이면 안 된다 — 이유가 "지저분해서"가 아니다

선은 카메라에 가까워 **depth가 250~350mm쯤**으로 잡힌다. 그러면:

- 부품 대역(400~600mm) **밖**이라 평가에선 잘린다 → 학습엔 직접 안 들어감
- 🔴 **그런데 `all_valid%`는 올린다**(유효 픽셀이므로)
  ⇒ ⭐**배경재 판정이 왜곡된다** — 용지는 멀쩡한데 선 때문에 유효율이 높게 나오면
  *"용지가 850nm에 안 통한다"* 로 **오판**할 수 있다
- 🔴 **선이 상자 위로 늘어져 부품 대역에 걸치면** 학습 데이터에 **잡음으로 들어간다**
  (라벨은 없는데 형체는 있으니 모델이 헷갈린다)

### ✅ 현실적 기준 = **"빈 안에만 안 들어오게"** (8/14 확정)

선을 전부 숨기는 것은 현실적으로 어렵다. **다행히 그럴 필요가 없다** —
두 피해의 심각도가 다르고, **심각한 쪽은 이것만으로 막힌다**:

| 피해 | 심각도 | "빈 안 회피"로 막히나 |
|---|---|---|
| **부품 대역에 걸쳐 학습 잡음** | 🔴 **심각** | ✅ **막힌다** |
| `all_valid%` 상승 → 판정 왜곡 | 🟡 보통 | ❌ 남는다 |

⭐ **첫 번째가 진짜 문제다** — 라벨 없는 형체가 부품 옆에 있는 것이 최악이고,
**빈 안만 피하면 사라진다.**

**남는 두 번째의 대응** = 🥇**배경재 판정 때만 선을 잠깐 치운다.**
판정은 5~10장·30분이므로 그동안만 옆으로 빼두면 **용지 자체의 성능을 깨끗하게 잰다.**
본촬영은 선이 좀 보여도 된다(부품 대역 밖이면 평가에서 잘린다).

🚨 **단 하나 — 선이 매 장면 같은 자리에 있어야 한다.**
장면마다 흔들리면 모델이 그것을 **배경 변화로 학습**한다.
⇒ **종이테이프로 한 번 고정하면 끝**이다.

⚠️ Blaze는 **108° 초광각**이라 생각보다 잘 들어온다 → **첫 장 찍고 화면에서 확인**.

## 2. 📐 물리 세팅

```
   [Blaze 카메라]  ← 부품 표면에서 450~470mm
         │
   ┌─────┴──────────────────────┐
   │   공구상자 (450×270×120)    │  ← 부품을 여기 담는다
   └────────────────────────────┘
   ▓▓▓▓▓ 차광 용지 (66.5×68cm 이상) ▓▓▓▓▓  ← 테이블 자리를 통째로 덮는다
   ═══════════ 테이블 ═══════════
```

- 🚨 **거리는 "상자 바닥"이 아니라 "부품 표면" 기준** — 상자 깊이 120mm만큼 부품이 올라온다
- 🚨 **용지는 빈 자리를 통째로 덮는다** — 인식 영역이 450mm에서 **823×464mm**라
  상자(450×270)만으론 화면 절반이 맨 테이블이다(= c2 조건 = F1 0.0814)
- 🚨 **종이테이프로 평평하게 고정** — 주름은 depth에 무늬를 만든다
- ⭐ **상자 테두리가 화면에 크게 들어오지 않게** — c2가 정확히 그것 때문에 무너졌다

**소량 추가(7장)는 이미 실패**했고, **이번 30~50장도 안 되면** 원인이 다른 데 있다:
- **종류 식별은 센서 물리 한계**일 수 있다(KAIST 결론 = depth-only 종류혼동 3유형)
- ⇒ 그때는 **RGB 융합 D단계**(ACE2로 종류 식별)가 다음 수다. 정합은 7/31에 이미 통과했다.

⭐ **그래서 이번 촬영에서 종류 커버리지를 반드시 확보해야 한다** — 커버리지가 부족한 채로
실패하면 *"데이터가 모자란 건지 센서 한계인지"* 를 **또 구분 못 한다.**
