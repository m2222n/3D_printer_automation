# GigE 카메라 IP 영구 고정 절차 (2026-07-29 확립)

> **배경**: 7/28 재택 작업 후 재부팅 → 7/29 아침 카메라가 안 열려 **1시간 이상 소모**.
> 원인이 한 겹이 아니라 **세 겹**이었다. 하나만 고쳐도 안 되므로 전부 확인할 것.
> ⭐ 핵심 규칙(7/28 확립) = **카메라 IP 대역 = 그 카메라가 꽂힌 랜포트 대역**

## 왜 날아가는가 — 임시 설정 3종

| # | 대상 | 임시 방법(재부팅 시 소멸) | 영구 방법 |
|---|---|---|---|
| ① | **셸 환경변수** | `export BASLER_ACE2_IP=...` | 쓰지 않기 / `.zshrc`에 있으면 최신값으로 |
| ② | **맥 랜포트 IP** | `sudo ifconfig en10 192.168.30.1 ...` | 시스템 설정 > 네트워크 > **수동** |
| ③ | **카메라 IP** | `ForceIp` (`set_gige_ip.py`) | pylon **IP Configurator** > Static IP |

⚠️ **①이 가장 헷갈린다** — ②③을 영구 고정해도 환경변수가 남아 있으면 스크립트가 옛 IP를 본다.
7/29 실제로 `BASLER_ACE2_IP=192.168.20.20`(옛값)이 스크립트 기본값 `192.168.30.20`을 덮어써서
"IP는 맞는데 왜 안 열리나"로 헤맸다. `BASLER_BLAZE_IP`는 우연히 맞아서 **Blaze만 열리는 비대칭**이 생겨
원인 파악이 더 늦어졌다.

## 현재 구성 (7/29 기준)

| 대상 | 값 | 비고 |
|---|---|---|
| Blaze-112 | `192.168.20.10` / SN 40737830 / MAC `00305337BB6E` | en8에 물림 |
| ACE2 (a2A2448) | `192.168.30.20` / SN 41881328 / MAC `003053381ABC` | en10에 물림 |
| 맥 en8 | `192.168.20.1/24` | ipTIME U1G-C, MAC `b0:38:6c:f7:e3:01` |
| 맥 en10 | `192.168.30.1/24` | MAC `b0:38:6c:f7:e5:50` |

⚠️ **7/20 기록과 카메라가 반대다**(7/20=ACE2 20/Blaze 30). "7/20 구성 복원"은 틀린 목표 —
**그때그때 배선에 맞추는 게 정답**. 배선을 바꿨으면 이 표도 갱신할 것.

## 절차 (순서 지킬 것)

### ① 환경변수 확인
```bash
env | grep BASLER                       # 이 셸에만 있는 것
grep -n BASLER ~/.zshrc ~/.zprofile     # 파일에 박힌 것
```
- 셸에만 있으면 → 새 터미널을 열거나 `unset BASLER_ACE2_IP BASLER_BLAZE_IP`
- 파일에 있으면 → 최신 IP로 수정하거나 **삭제**(스크립트 기본값이 이미 맞다)

### ② 맥 랜포트 IP 영구 고정 (GUI, 카메라보다 먼저)
시스템 설정 > 네트워크 > **해당 IP로 표시된 어댑터** 선택 > 세부사항 > TCP/IP
> IPv4 구성 = **수동** / IP `192.168.30.1` / 서브넷 `255.255.255.0` / 라우터 **비움**

⚠️ 어댑터 2개 이름이 비슷하다(`USB 10/100/1000 LAN` 등) → **현재 IP로 구분**할 것.
⚠️ 랜포트가 30 대역이 아니면 다음 단계에서 ACE2가 보이지 않는다.
⚠️ DHCP면 실패 시 `169.254.x.x`(APIPA)로 떨어진다 — 아침에 이 상태였다.

### ③ 카메라 IP 영구 고정 (pylon IP Configurator)
응용 프로그램 > pylon > **IP Configurator** (pylon Suite 26.04에 포함, 이미 설치됨)
카메라별로: 선택 > **Static IP** > IP/서브넷 입력(게이트웨이 `0.0.0.0`) > **Save**

⚠️ **잘 되고 있는 카메라도 반드시 하라.** 7/28~29에 Blaze는 멀쩡하고 ACE2만 날아갔는데,
Auto/DHCP 상태면 언제든 반대가 된다.
⚠️ 오버레이·뷰어가 카메라를 쥐고 있으면 접근 실패 → **먼저 종료**.

### ④ 재부팅 검증 (이걸 해야 "고정됐다"고 말할 수 있다)
```bash
ifconfig en10 | grep "inet "                  # 192.168.30.1 유지?
python bin_picking/tests/set_gige_ip.py       # 두 카메라 IP 유지?
```

## 증상별 진단표

| 증상 | 원인 | 확인 |
|---|---|---|
| **열거는 되는데 열기만 timeout**<br>(`Failed to download the XML`, `0xe101800b`) | 카메라 IP 대역 ≠ 꽂힌 포트 대역.<br>열거=브로드캐스트(전 포트), 열기=유니캐스트(정확한 포트) | `arp -an \| grep <MAC>` → `on en8` 식으로 실제 포트 확인.<br>ARP가 비면 최근 통신이 없던 것(ping 유도) |
| `Failed to discover GigE device 'X'` | 스크립트가 **없는 IP**를 보고 있음 | ⭐**에러에 찍힌 IP를 먼저 읽어라.** 환경변수가 기본값을 덮어썼을 수 있다 |
| 열거 0대 | 카메라 IP가 어느 포트 대역과도 안 맞음(고아) | `set_gige_ip.py`로 대역 맞추기. 직전에 랜포트 IP를 바꿨으면 특히 의심 |
| 랜포트가 `169.254.x.x` | 수동 IP 소멸 → DHCP 실패 → APIPA | ②로 영구 고정 |
| Blaze가 ping 무응답 | **정상** — Basler ToF는 ICMP 응답 안 함 | ACE2는 응답한다 |

## 교훈

1. **원인이 여러 겹일 수 있다.** ②를 고쳤는데 안 되면 ①·③을 의심할 것. "하나 고쳤는데 왜 안 되지"에서 시간을 잃었다.
2. **에러 메시지의 IP를 먼저 읽어라.** `Failed to discover '192.168.20.20'`이 환경변수 문제를 바로 가리켰다.
3. **비대칭 증상은 힌트다.** 한 카메라만 열리면 공통 원인(드라이버·전원)이 아니라 **그 카메라 고유 설정**을 봐야 한다.
4. **임시 명령으로 넘긴 것은 반드시 돌아온다.** 7/28에 "작업 끝나고 권장"으로 미룬 IP Configurator가 다음 날 아침 1시간을 잡아먹었다.
