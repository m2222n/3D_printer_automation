# 재촬영 체크리스트 (2026-08-10 작성)

> **왜 재촬영인가** — 8/7 재학습이 실패했다. c1 실측 7장을 추가했더니 holdout F1이
> **0.4231 → 0.2917**로 떨어졌다(87장 중 7장 = 8%뿐이라 일반화가 아니라 과적합).
> ⇒ **소량 추가라는 경로는 막혔고, 학습 조건에 맞춘 수십 장 재촬영이 다음 수**다.

⭐ **북극성 자문**: 이 촬영이 "카메라가 잘 인식"에 기여하는가 → **직결**(인식 정확도가
8/5 회의 이후 사업 성과 지표 그 자체다).

---

## 0. 선행 조건 — 이게 없으면 찍어도 소용없다

| 조건 | 상태 | 비고 |
|---|---|---|
| 상자(부품 담기) | ⏳ **발주 요청함**(8/10) | 공구상자 1호 브라운 450×270×120mm ×2 |
| 배경재(배경 지우기) | ⏳ **사내 보유 차광 용지** | 🚨**850nm에서 통하는지 미검증** → §2에서 먼저 판정 |
| 부품 | ✅ 보유 | ⚠️**재택 촬영 시 부품을 가져와야 한다**(8/11 출근 때 챙길 것) |

🚨 **상자와 배경재는 역할이 다르고 서로 대체 불가**다.
상자 = 부품을 모아 담기(없으면 좌표 범위가 무한정) / 배경재 = 배경을 depth상 지우기
(없으면 배경이 부품으로 오검출). ⭐**상자만 놓으면 화면의 절반 가까이가 맨 테이블로 남는다**
(인식 영역 823×464mm vs 상자 450×270mm).

---

## 1. 촬영 설정 — 바꾸면 안 되는 것

⭐ **원칙 = 물리 환경만 바꾸고 센서 설정은 전부 고정한다.**
설정을 같이 바꾸면 성능이 떨어졌을 때 **"일반화 실패"인지 "설정 불일치"인지 구분이 안 된다.**
(7/6에 실제로 LongRange로 찍혀 g2·g3 품질이 떨어진 사고가 있었다.)

| 항목 | 값 | 🔴 타협 불가 사유 |
|---|---|---|
| 모드 | **ShortRange** | 7/6 사고 |
| 필터 | **On** | 학습 조건 |
| 해상도 | **848×480 uint16 raw** | 평가 파이프라인 입력 규약 |
| **작업거리** | ⭐**444~483mm**(학습 대역) | 평가가 `--depth_keep_range 0.40,0.60`으로 **부품 대역만 남긴다** → 벗어나면 **검출 0건** |
| 부품 위치 | **화면 중앙 2/3 안** | `--center_crop '1/6,5/6'` — 가장자리는 평가에서 잘린다 |

⚠️ **7/29 재택에서 이것 때문에 실패한 적이 있다** — z 중앙이 4.1~4.6m(커튼·창밖)로 잡혀
커버리지 0.4~3.4%였다. 원인은 Blaze가 **108° 초광각**이라 50cm 물체가 화면의 극히 일부였던 것.
→ **화면 하단 DIST 게이지로 현장에서 즉시 확인할 것.**

🚨 **거리는 "상자 바닥"이 아니라 "부품 표면" 기준**이다. 상자 깊이 120mm만큼 부품이 올라온다.

## 2. 배경재 판정 — 찍기 전에 30분

> 🚨 **눈으로 고를 수 없다.** 가시광 차광 ≠ 850nm 흡수. 검게 보여도 근적외선을 반사하면
> 배경이 depth로 채워져 c3(F1 0.0000)가 된다.

**순서**
1. 배경재를 깔고 **부품 몇 개 올린 상태**로 5~10장 촬영
2. 판정: `python tests/check_background_material.py <촬영폴더>`
3. 후보가 여럿이면: `--labels 차광용지 무광시트` 로 나란히 비교

**판정 기준** (8/5 실측 30장, 2026-08-10 재현 확인)

| 조건 | 유효율 | F1 | 판정 |
|---|---|---|---|
| **c1**(택배상자 안 = 학습 조건) | **4.27~7.50%** | **0.4070** | ✅ 목표 |
| c2(상자 테두리 노출) | 24.90~38.25% | 0.0814 | 🟠 박스를 부품으로 오인 |
| c3(흰 테이블 직접) | 80.04~94.74% | 0.0000 | 🔴 부품 자리를 아예 안 봄 |

- 🟢 **통과** = 8할 이상이 학습 분포(2~25%) 안, 이상적으로는 **c1의 4~8%대**
- 🔴 **부품 대역이 0.5% 미만이면 통과여도 실패** — 배경이 사라져도 **부품이 안 잡히면 소용없다**

🚨 **종이는 말리거나 주름이 진다** — 매트가 주름지면 depth에 무늬가 생긴다.
**평평하게 눌러 고정**할 것. 안 되면 시트지를 데이터와 함께 재요청한다(근거가 있으면 설득이 쉽다).

⭐ **암막 커튼은 역할이 다르다** — 커튼은 **외광(창문 빛)** 차단, 배경재는 **테이블 배경 지우기**.
공장 빛은 *"커튼 없이 그냥 간다"*가 방침이므로 지금은 커튼을 쓰지 않는다.

## 3. 본촬영 — 몇 장을, 어떻게

⭐ **목표 = 수십 장**(8/7 결론). **소량은 과적합으로 확정**됐으므로 7장 같은 규모는 의미가 없다.

**⭐ 학습 데이터의 8%가 아니라 유의한 비중이 되어야 한다** — 기존 학습이 87장이므로
**최소 30장, 가능하면 50장 이상**이라야 분포를 실제로 움직인다.

**구성**
- 부품을 상자에 **무작위로 쏟아 담고** 매번 흔들어 자세를 바꾼다
  (⭐ 무작위 적재는 **안정 자세로 수렴**한다 = 가장 얇은 면이 바닥에 닿는다)
- **겹침 60% / 펼침 40%** 비율(6/26 100장 촬영에서 쓴 배분)
- 종류를 골고루 — 학습 27종 기준. ⚠️**공정 대상 19종으로 줄이지 말 것**
  (제외 4종도 카메라엔 보이므로 학습에서 빼면 다른 부품으로 오인한다)

**촬영 중 확인**
- [ ] DIST 게이지가 **444~483mm** 안인가
- [ ] 부품이 **화면 중앙 2/3** 안에 있는가
- [ ] 상자 테두리가 화면에 크게 들어오지 않는가 (c2 조건 회피)

## 4. 찍고 나서 — 바로 판정

```bash
# 유효율이 학습 분포 안인가
python tests/check_background_material.py <촬영폴더> --with-baseline
```

⚠️ **이 판정은 "학습 분포 안에 들어오는가"까지만 답한다.**
**F1이 얼마나 나오는지는 라벨링을 해야 안다** — 통과가 곧 성능 보장은 아니다.
(7/31에 라벨 없이 "폭락 재현 안 됨"으로 판단했다가 8/5에 뒤집힌 전례가 있다.
⭐ **"몇 개 찾았나"와 "맞게 찾았나"는 다른 질문이다.**)

⏭️ 통과하면 → 라벨링 → 학습 데이터에 합쳐 재학습 → **holdout으로 검증**
🚨 **재학습 시 반드시 지킬 것**(8/7에 확립):
- **누수 0 확인**(train ∩ holdout = 공집합)
- **기준선을 먼저 재현**(38/43/67%) — 이게 없으면 하락이 모델 탓인지 평가 설정 탓인지 못 가른다
- **test102 회귀 검사**(기존 성능이 안 떨어지는가)
