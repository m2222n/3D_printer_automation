**둘 사이 변환을 구하는 것**이 hand-eye다.

⭐ **3점법** = 같은 물리적 3점을 **①카메라로 보고 ②로봇으로 찍어서** 변환을 푼다.

### ⚠️ 왜 기존 `hand_eye_calibration.py`(1155줄)를 안 쓰는가

**버리지 않는다. 다만 지금 목적에 맞지 않는다.**

```
        빈(택배 상자) 위에서 본 그림

     P4 ●───────────────● P3
        │               │        ⭐ 규칙 3개
        │   (부품 영역)  │        ① 넓게 벌린다 (최소 50mm, 가능하면 150mm+)
        │               │        ② 한 직선에 놓지 않는다
     P1 ●───────────────● P2     ③ 부품이 놓이는 영역을 감싼다
        └── X축 방향 ──→
```

⭐ **4점 이상 권장.** 3점이면 점 하나가 1mm 틀려도 **조용히 기울어진 좌표계**가 나온다.

📌 코드가 이것을 강제한다 — 잔차 **5mm 초과면 예외를 던지고 좌표를 보내지 않는다.**

### 🟢 이미 있는 것
- **계산 코어** = `hand_eye_calibration.py`가 `cv2.calibrateHandEye()` 4메서드 + **eye-in-hand 수식**까지 구현.

### ✅ [9/10 재택] 신설 2건 — 코드 완료 · 시뮬·자체 테스트 통과 · **실물 0회**

   🚨 "다음 자세까지 연결을 열어 두는" 설계는 안 된다 — `socketReadLine` 상한 15000ms(9/7 실측). 사람이 로봇을 옮기고 다시 ▶.
   ⭐ GUI 로는 `[move P1 → script → move P2 → script …]` 로 같은 script 노드를 복붙하면 한 프로그램으로 된다.
   시뮬 ⑳(`simulate_rodi_pick.js`) = 로봇 안 움직임 · 원값 그대로 · 순서 · OK/ERR 로그 분기.
