# 빈피킹 현 위치 총정리 (2026-07-30 기준)

> 헷갈리기 쉬운 이유 = **인식 트랙이 2개**(Blaze depth / ACE2 RGB)이고, **ACE2는 캘리브만
> 해놓고 아직 인식에 쓰지 않는다**. 지금 돌아가는 파이프라인은 **Blaze 단독**이다.
> 또 캘리브·좌표·통신은 "로봇 없이 되는 일"이라 많이 진행됐고, 정작 **북극성의 핵심
> (실환경 인식·로봇)은 손을 못 댄 상태**다.

## 북극성 기준 현 위치

```
학습이 잘 됨   →   카메라가 잘 인식   →   로봇이 빈피킹을 잘 수행
   ✅ 천장           ⚠️ 미검증               ❌ 미착수
 (F1 0.684~0.818)  (실물 부품 인식 0회)   (hand-eye 없음)
```

⚠️ **캘리브는 "인식할 준비"이지 인식이 아니다.** (7/28 격차분석 결론, 여전히 유효)

## 1. 카메라 — 어디까지 됐나

| 항목 | Blaze-112 (ToF depth) | ACE2 (RGB 5MP) |
|---|---|---|
| 연결·촬영 | ✅ (7/20 throughput 10Mbps 튜닝) | ✅ |
| IP 영구고정 | ✅ 7/29 (`setup_camera_net.py --apply` 한 줄) | ✅ |
| **intrinsic** | ✅ **RMS 0.213px** (7/28 실측) | ✅ RMS 0.546px (7/20) |
| **둘 사이 정렬(extrinsic)** | ✅ **산포 5.29mm**, x=+44.7mm·회전 1.78° (자 실측과 1.7mm 차) | ✅ 같은 값 |
| **인식 모델** | ✅ depth_track (F1 0.818) | ❌ **없음** |
| **6요소 좌표 출력** | ✅ 7/29 완성 (801건·z 100%) | ❌ |
| **오버레이 정합 검증** | ❌ **미완** (재택 조건 불가 → 금요일 공장) | ❌ 미완 |

⭐ **결론: "빈피킹을 돌리는 데 필요한 카메라 작업"은 거의 다 됐다** (Blaze 단독으로 좌표까지 나옴).
🔴 **단 남은 1건 = 오버레이 정합 검증.** 두 카메라를 겹쳐 눈으로 맞는지 보는 것. 이게 안 되면
   RGB 융합을 못 얹는다(정렬값이 맞는지 확인이 안 됨).

## 2. ⚠️ "RGB 융합"의 실체 — 준비만 했고 융합은 안 했다

7/20에 "RGB 융합 착수"로 기록했지만 실제로 한 것은 **A단계 = 캘리브(준비)** 뿐이다.

| 단계 | 상태 |
|---|---|
| A. ACE2 렌즈·intrinsic 캘리브 | ✅ 7/20 |
| B. 두 카메라 정렬(extrinsic) | ✅ 7/28 (값은 나왔고 **검증 미완**) |
| C. 정합 코드(`rgbd_fusion.py`) | ✅ 7/28 (테스트 15/15, **실물 미적용**) |
| D. **RGB로 종류 식별** | ❌ **모델이 없다** |
| E. depth+RGB 융합 판정 | ❌ |

🔴 **D가 핵심인데 미착수**다. RGB로 무엇을 할지도 7/29에 바뀌었다:
  - 7/28까지: 1순위 = 표면 패턴 구분
  - **7/29 이후: 1순위 = `07/09_guide_paper` 치수차**(그리퍼 벌림 20mm 차 = 물리적으로 안 들어감)
  - 7/30 추가: **불량 검출**(표면·색 불량은 depth로 불가)

## 3. 로봇 — 통신은 됐고 좌표 변환이 통째로 빔

| 항목 | 상태 |
|---|---|
| Modbus 8단계 핸드셰이크 | ✅ 7/30 시뮬 검증(28/28) |
| 6요소 → INT16 인코딩 | ✅ 실측 801건 왕복 오차 0 |
| 회전각(angle) | ✅ 7/30 해소 (98.8%) |
| **레지스터 번호 확정** | ⏸️ 협력사 회신 대기 (140~149 제안) |
| `PC_READY_OFF_DELAY=4초` 이유 | 🚨 **미해명** — 실물 붙일 때 확인 |
| **hand-eye 캘리브** | ❌ **미착수 = 로봇 필수** |
| 실제 피킹 | ❌ |

🔴 **hand-eye가 없으면 로봇은 절대 못 움직인다.** 좌표가 지금 **카메라 기준**이라
   로봇 기준(Base)으로 바꾸는 변환이 통째로 비어 있다. 로봇 전원·펜던트 필요.

## 4. 🚨 가장 큰 리스크 = 실환경 인식 미검증 (변함 없음)

F1 0.818은 **학습에 쓴 세션**으로 낸 값이다(2세션 다 학습에 포함 → 리포 데이터로는 **원리상
검증 불가**). 즉 **"처음 보는 환경에서도 되는가"는 아직 답이 없다.**

⚠️ **같은 함정 전례**: 세척기 분류가 같은 세션 0.982 → **cross-session 0.34~0.70 폭락**.
   depth_track엔 이 검증을 **한 번도 안 했다.**

→ **새 세션 촬영이 유일한 길**(금요일 공장, 스크립트 준비 완료).
→ 여기서 무너지면 각도·좌표·통신이 다 빈 껍데기가 된다. **그래서 이게 1순위다.**
