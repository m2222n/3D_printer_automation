# 🔧 문제 대응

## A. 카메라가 안 열림 (`Failed to download XML` / discover 실패)
⭐ **에러에 찍힌 IP를 먼저 읽어라** — 7/29에 이 한 줄이 정답을 가리켰다.

1. **셸 환경변수 확인**(가장 흔한 원인)
   ```bash
   env | grep BASLER
   ```
   옛 IP가 있으면 `unset BASLER_ACE2_IP BASLER_BLAZE_IP`
2. **랜포트 IP 확인** — `ifconfig | grep -A3 en` → `169.254.x`(APIPA)면 소멸된 것
   → `sudo python bin_picking/tests/setup_camera_net.py --apply`
3. **실제 물린 포트 확인**
   ```bash
   arp -an | grep -i <MAC>     # → "on en8" 식으로 찍힘
   ```
   ⭐ 규칙 = **카메라 IP 대역 = 그 카메라가 꽂힌 랜포트 대역**.
   어긋나면 **열거(발견)는 되는데 열기만 timeout**(열거=브로드캐스트, 열기=유니캐스트)
4. **케이블 반대로 꽂았나** 확인(7/28 실제 원인이 이것이었음)
5. IP Configurator로 Static 확인(F5 Refresh)

## B. ShortRange 오류로 스크립트가 종료됨
의도된 동작이다(경고 아니라 종료). pylon Viewer에서 `OperatingMode`를 ShortRange로
바꾸고 재시도. **이걸 무시하고 찍으면 그 데이터는 해석 불가**가 된다.

## C. 🚨 DIST가 3000mm 근처로 뜨는데 실제로는 50cm 촬영
**단위 스케일 문제.** 저장 npy는 `raw × 10/65535`가 mm인데, 라이브 값이 이미 mm일 수 있다
(현장 확인 미완). 이때만:
```bash
sudo python blaze_capture_crosssession.py --scale 2 --raw-is-mm
```
> 저장 원본은 어느 쪽이든 raw 그대로라 **데이터는 안전**하다. 판정 표시만 달라진다.

## D. 촬영 중 스크립트가 죽음
`capture_meta.json`과 npy는 **매 장 즉시 저장**되므로 유실 없다.
다시 실행하면 **마지막 번호 다음부터 이어찍기**된다(조건 번호도 이어짐).
