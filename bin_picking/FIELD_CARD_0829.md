## 1. 로봇 → IPC 소켓 (30분)

🚨 **로봇이 클라이언트, 우리가 서버**다. 그래서 **IPC IP를 로봇 스크립트에 넣어야** 한다.

```powershell
# IPC — 서버를 먼저 띄운다 (🚨 로봇이 붙기 전에)
python bin_picking\src\communication\pick_socket_server.py --mode handshake
ipconfig     # ⭐ 이 IP 를 로봇 스크립트 SERVER_IP 에 넣는다
```

```javascript
// 펜던트 — rodi_pick_sequence.js 의 설정만 바꿔 먼저 통신만 본다
var MODE = 'vision';
var SERVER_IP = '<위 ipconfig 값>';
```

| 판정 | 기준 |
|---|---|
| 🟢 성공 | 서버에 접속 로그 + 로봇이 `DONE` 전송 |
| 🔴 실패 | 아래 순서로 본다 |

**막히면 이 순서** (추측하지 말고):
1. **같은 대역인가** — 🚨 *"IP 대역 = 꽂힌 랜포트 대역"*([[gige-camera-network-rule]] 확장)
2. **Windows 방화벽** — 5000 인바운드 허용
3. `socketOpen` 실패는 **7초 후 재시도**한다(ko:172) — 바로 포기하지 말 것

⭐ **`--mode handshake`는 빈 배열을 보낸다 = 로봇이 안 움직인다.** 통신만 확인하는 단계다.

## 2. Blaze → IPC 실취득 (40분) — 🚨 여기가 진짜 관문

> 8/14 기록 = *"여기서만 OS 판단이 뒤집힐 수 있다"*
> ⚠️ 맥에서 **카메라 네트워크에 세 시간** 썼다. IPC는 Windows라 절차가 다르다.

```powershell
python -c "from pypylon import pylon; print(len(pylon.TlFactory.GetInstance().EnumerateDevices()))"
```

| 결과 | 뜻 |
|---|---|
| `1` 이상 | 🟢 다음으로 |
| `0` | 🔴 **네트워크 문제**(카메라 고장 아님) |

**`0`이면 이 순서** — 8/24 확립 절차가 그대로 적용된다:

1. 🚨 **IP 대역 확인** = `arp -a` 로 카메라 MAC 이 보이나
2. **Blaze `.20.10` ← 랜포트 `.20.1`** (8/24 확립값. 🚨 **호스트를 `.20.2`로 바꾸면 안 열린다**)
3. pylon IP Configurator 로 확인
4. ⚠️ **열거 0대가 정상인 경우도 있다** — 어댑터가 없으면(맥 교훈)

⭐ 취득되면 **1장 찍어 6000 기준선과 대조**:
```powershell
python bin_picking\src\run_binpick_e2e.py --depth-dir <취득폴더> --out-dir field1
python bin_picking\depth_track\scripts\compare_e2e_results.py --ref <기준선> --test field1
```
🚨 **새로 찍은 장면은 기준선에 없다** — 이 대조는 **§6의 저장된 npy 로** 한다.
현장 취득분은 *"찍히나 · 대역이 맞나(BAND 3~10%)"* 만 본다.

## 3. 그리퍼 장착 + 개폐 (40분)

🚨🚨 **가장 큰 미확인** = 배선이 **3가지 중 무엇인가**

| 후보 | 근거 | 확인법 |
|---|---|---|
| **A. 도구 디지털 I/O** | `ko:58~60` | 그리퍼 케이블이 **로봇 말단 커넥터**에 |
| **B. RS485 + Modbus RTU** | `ko:123~124` | ⭐ 되면 **위치·힘 지정 가능**(벌림 15점 살아난다) |
| **C. 시리얼** | `ko:181` | |

⭐ **먼저 그리퍼 자체 매뉴얼/라벨을 본다** — JEGB-4285P 커넥터 핀 배치가 답을 준다.

```javascript
// 스크립트 설정만 바꿔서
var MODE = 'gripper';          // ⭐ 로봇이 움직이지 않는다
var GRIPPER_MODE = 'dio';      // 안 되면 'serial'
```

| 판정 | 기준 |
|---|---|
| 🟢 | **눈으로 열고 닫힘** 3회 |
| ⭐ | `getToolDigitalInput` 이 **뭔가 값을 준다** → 파지 확인 배선이 있다 |
| ⚠️ | 항상 `0` → **배선 없음.** P5 성공률을 **사람이 세야 한다**(치명적이지 않음) |

🚨 **페이로드를 반드시 설정한다** — `setPayload(1.5)`. 안 하면 **충돌 감지가 오작동**(ko:129).
🚨 **TCP 확인** — 펜던트에 `a_0115`(Z=200)가 이미 있다. **덮어쓰지 말고 현재값을 먼저 읽는다.**

## 4. 3점 티칭 (40분)

📌 절차 전체 = `docs/HAND_EYE_CARD.md` §3. 요약만 적는다.

```
     P4 ●───────────────● P3     ⭐ 규칙
        │  (부품 영역)   │        ① 최소 50mm, 가능하면 150mm+
     P1 ●───────────────● P2     ② 일직선 금지  ③ 부품 영역을 감싼다
```

- [ ] 로봇으로 4점 찍어 좌표 기록 (`getCurrentPose('tcp')`)
- [ ] 카메라로 같은 4점의 depth 좌표
- [ ] `solve_rigid_transform(cam, rob)` → **잔차 확인**

| 지표 | 🟢 | 🔴 |
|---|---|---|
| RMS 잔차 | **< 3mm** | ≥ 5mm (코드가 예외를 던진다) |
| 스케일 비 | 0.98~1.02 | 벗어나면 **단위 실수** |

🥇 **검산 = 캘리브에 안 쓴 5번째 점**으로 예측 vs 실측 (train-on-test 회피)

## 5. ⭐ 정지 파지 (40분) — **인식 없이**

```javascript
var MODE = 'teach';
var TEACH_POSE = [ /* 펜던트로 티칭한 부품 위 좌표 */ ];
```

🚨 **사람이 정지 버튼에 손을 두고 시작한다.**

**순서** (스크립트가 이대로 한다):
접근 상공(z+80) → 열기 → **저속 하강** → 닫기 → **페이로드 갱신** → 상승(z+120) → 파지 확인

| 판정 | 기준 |
|---|---|
| 🟢 **성공** | 부품이 그리퍼에 들려 올라온다 |
| 🟡 부분 | 움직임은 맞는데 못 집음 → **높이(z) 또는 벌림** |
| 🔴 실패 | 엉뚱한 곳 → **좌표계** (4번 재확인) |

⚠️ `PLACE_POSE`가 비어 있으면 **들고 정지한다**(의도된 동작). 놓을 자리는 성공 후 티칭.
