# KAIST 미팅 공유 자료 (7/3 목 14:00)

> 프로젝트 목표 = **3D(depth) 이미지만으로 부품을 식별(분류)하는 모델.**
> 지난 미팅 이후 우리가 (1) 받은 피드백을 어떻게 해결했고, (2) 지금 상황이 어떻고, (3) 나아지려고 무엇을 시도했는지 정리.

> ### 📌 30초 요약
> - 합성으로 학습한 모델을 **실측 100장에 처음 적용** → 검출은 완벽(recall 1.0)한데 **식별(class acc)이 80%→5%로 붕괴** = 전형적 sim2real 도메인 갭, 하필 프로젝트 핵심 KPI에서 터짐.
> - **원인을 재학습 실험 3종으로 규명** → **진범 = 스케일(카메라 거리) 갭.** cam_h 스윕 재학습으로 **실측 5% → 39.6%(약 8배)** 회복. 노이즈 aug 단독은 13.6%로 미미했고 합성 성능까지 깎음.
> - 남은 격차(합성 61% vs 실측 40%, 약 21%p) = 잔여 도메인 갭 → **미팅에서 aug 방향·baseline 함께 정하고 싶음.**

## 2. 지금 상황 (핵심 결과)

### ⭐ 합성으로 학습한 모델을 실측 100장에 처음 적용해봤다

| 지표 | 합성 test (6/24, 850 obj) | **실측 100장 (7/2, 872 obj)** | 결과 |
|------|--------------------------|------------------------------|------|
| recall (검출·위치) | 1.00 | **1.00** | 유지 ✅ |
| mask IoU (윤곽) | 0.855 | **0.731** | 준수 |
| box IoU | 0.682 | 0.531 | 준수 |
| **class acc (부품 식별)** | **0.804** | **0.050** | **붕괴** 🔴 |
| **CAD acc (CAD 식별)** | **0.798** | **0.049** | **붕괴** 🔴 |

### 한 줄 요약
> **"어디에 뭐가 있고 어떻게 생겼나(검출·마스크)"는 실측에서도 잘 되는데, "그게 27종 중 무엇이냐(식별)"는 무너진다.**
> class acc 5% ≈ 27종 랜덤 추측(1/27 = 3.7%) 수준 → **전형적인 sim2real 도메인 갭이며, 하필 프로젝트의 핵심 KPI(depth-only 식별)에서 터짐.**

이게 **프로젝트 최대·본질 문제**입니다 (회사 빈피킹 목표와 별개로, "depth-only 식별 모델"이 프로젝트 목표이므로 이 5%가 곧 성능 그 자체).

### ⭐ 그리고 이 5%를 재학습으로 39.6%까지 회복시켰다 (§3 참조)

| 학습 데이터 | 실측 class acc | 실측 CAD acc | 실측 mask IoU | 합성 test class acc |
|------|:---:|:---:|:---:|:---:|
| 기존 (원본 합성, 6/23) | 5.0% | 4.9% | 0.73 | 80.4% |
| **cam_h 스윕 (스케일 정합)** | **39.6%** ⭐ | **38.8%** | 0.79 | 60.9% |
| ToF 노이즈 aug | 13.6% | 12.2% | 0.77 | 56.1% |

> **재학습 한 번으로 실측 식별이 5% → 39.6%. 스케일(카메라 거리)을 실측에 맞춘 것이 결정타였다.**

## 3. 나아지기 위해 시도한 것들

> 흐름: (1) 데이터 입력이 멀쩡한지 먼저 증명 → (2) 진단으로 가설 → (3~4) 재학습 실험으로 진범 확정.

### 시도 1 — 정규화가 3.5배 스케일 오류를 흡수하는지 증명 ✅
- `robust_normalize_depth`(median 빼고 p95−p05로 나눔)는 **임의 선형 배율 k를 완전 상쇄**.
- 실측 raw에 ÷3.5, ×2, ×3.5를 곱해 정규화 → 결과 최대 차이 **≈ 0** (그림 1 오른쪽: 모든 배율 히스토그램이 완전히 겹침).
- **결론: 3.5배 저장 오류는 학습·평가 입력단에서 자동 소거 → 스케일 보정·재촬영 불필요 확정.** (이건 "절대 depth 배율" 축이고, 아래 시도 3의 스케일 갭은 "화면상 픽셀 크기/원근 프로파일"로 별개 축.)
- 0-1 정규화 부작용(부품 최저 픽셀이 배경으로 빠짐)도 장당 **최대 0.04%**로 무해 확인.

### 시도 2 — 진단으로 세운 가설, 그리고 실험이 뒤집은 것 (정직하게 기록)
재학습 전에 **크기 구간별 class acc**로 진범을 추정했습니다:

| 크기구간(GT px) | 개수 | class acc | mask IoU |
|---|---|---|---|
| 0~100 (작음) | 124 | 29.0% | 0.49 |
| 100~300 | 212 | 1.9% | 0.65 |
| 300~800 | 267 | 0.4% | 0.78 |
| 800~2000 | 152 | 2.0% | 0.82 |
| 2000+ (큼) | 117 | 0.0% | 0.91 |

- 진단 해석: "큰 부품일수록 오히려 식별 실패(상관 −0.37) → 스케일이 아니라 노이즈가 진범" 이라고 **예측**했음.
- ⚠️ **그러나 실제 재학습 결과가 이 가설을 뒤집음** (아래 시도 3). 위 표는 **스케일이 안 맞는 기존 모델의 증상**이었을 뿐 — 스케일을 실측에 맞춰 재학습하니 식별이 8배 회복. **"진단상 관찰"과 "개입 실험 결과"는 다르며, 실험이 진실**이라는 점을 명확히 함.

### 시도 3 — cam_h 스윕 재생성 + 재학습 = **진범이 스케일임을 확증** ⭐⭐
- 문제: 기존 합성은 카메라 0.36~0.44m 고정 + FOV를 거리에 맞춰 조정 → 부품이 항상 화면을 꽉 채움(근접·평면). 실측은 원거리·작게·곡면.
- 조치: `gen_one_2denc_camsweep.py` = **cam_h 0.4~1.0m 스윕 + FOV 고정**(멀수록 부품이 작게·곡면) → 1000장 재생성 → **재학습**(warmup 30ep → joint VQ 100ep).
- **결과: 실측 class acc 5.0% → 39.6% (약 8배), CAD acc 4.9% → 38.8%.** 검출·mask는 그대로 유지.
- ⭐ **결론: 진범 = 카메라 거리/원근 스케일 갭.** 합성을 실측 촬영 거리에 맞추자 식별이 살아남.

### 시도 4 — ToF 노이즈 aug 재학습 = 오히려 역효과
- 조치: cam_sweep 위에 **Blaze ToF 노이즈**(표면 gaussian + 경계 뭉개기 + dropout 구멍)를 입힌 데이터셋으로 재학습. (조교님 "경계 뭉개기 aug"를 우리가 선제 시도)
- **결과: 실측 class acc 13.6%에 그침** + 합성 test acc를 80% → 56%로 **깎음**.
- 해석: 우리가 넣은 노이즈 강도/방식이 과했을 가능성. **노이즈 aug는 방향은 맞을 수 있으나 강도 튜닝이 관건** → 조교님이 더 나은 aug를 고민 중이라면 이 결과를 반례로 공유하고 함께 조정하고 싶음.

### 남은 카드 (준비됨, 미팅 후 착수)
- **cam_h 상한 ↑ 스윕**(0.5~1.6m): cam_sweep이 방향은 맞았으나 부품이 아직 실측보다 큼(main_body 1530px vs 실측 407px). 상한을 올려 더 작은 부품 커버 시 39.6%가 더 오를지 검증. 스크립트 준비 완료(`gen_one_2denc_camsweep_hi.py`). **단, 부품이 너무 작아지면 정보 소실 위험 → 미팅서 상한/FOV 함께 결정 후 실행.**
- **cam_sweep + 약한 노이즈 결합**: 스케일 맞춘 상태에서 노이즈를 약하게 넣어 남은 21%p 갭을 줄이는지.
- **실측 소량 fine-tune**: 위가 부족하면 실측 일부로 도메인 적응.

## 4. 미팅 논의 안건

### 🥇 남은 도메인 갭(합성 61% vs 실측 40%, 약 21%p) 어떻게 줄이나 (7/9 완주 핵심)
1. **진범(스케일) 규명 + 39.6% 회복을 보고** → 다음 목표 = 이 21%p 격차 축소. 우리가 준비한 카드 3장(cam_h 상한↑ / 약한 노이즈 결합 / 실측 fine-tune) 중 **7/9 안에 뭐가 현실적인지** 조교님 판단.
2. **노이즈 aug 방향 조정** — 우리 노이즈 단독은 역효과(13.6%, 합성 성능도 하락)였음. **조교님이 고민 중인 aug 방식과 강도**를 공유받아, cam_sweep 위에 얹는 방식으로 재시도.

### 🥈 데이터 포맷 확정
3. **정규화 기준 통일** — valid 판정(`depth>0` vs `mask=inst_id>0`) / 0-1 스케일 기준(per-scene min-max vs 데이터셋 고정 상한). 합성·실측 동일해야 정합. (현재 39.6%는 per-scene 기준 결과)

### 🥉 비교 baseline 정의
4. 6/24부터 미해결. BOP(ITODD/IC-BIN) 다운 완료. **"무엇을 baseline으로, 어떤 지표로 비교표를 만들지"** 조교님과 합의 → 정의되면 우리가 어댑터 착수.

### 참고
5. modality 비대칭(6/25 Q&A, depth K-역투영 point 통일)이 남은 갭의 원인 후보인지. / 논문·특허는 종강(7/9) 이후.
