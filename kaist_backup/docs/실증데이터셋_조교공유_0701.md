# 실증 데이터셋 (real_capture100) — 공유 안내

> **팀6 → · 2026-07-01
> Blaze depth 카메라로 촬영한 **실물 부품 100장** + instance 라벨링 완료본. CADENCE 파이프라인의 **실증 평가셋(test)** 용도.

---

## 1. 한 줄 요약

- 합성 학습셋(`dataset_2denc`, 1000장)과 **동일 부품 27종 · 동일 category_id**로 촬영한 **실물 depth 100장**.
- labelme로 **instance 라벨링 완료**(부품별 mask + 라벨 이름).
- 합성 포맷(`depth 512×512 float32 m / 배경 NaN / inst_id / category_id`)과 **동일하게 변환**해 뒀습니다 → 학습된 detector에 그대로 넣어 **합성→실증 도메인 갭 평가**에 쓸 수 있습니다.

---

## 2. 촬영 개요

| 항목 | 내용 |
|------|------|
| 카메라 | Basler **Blaze**(ToF depth), top-down |
| 원본 해상도 | **848 × 480**, uint16, 단위 **mm** |
| 장수 | **100장** |
| 부품 | **27종**(합성과 동일). 색상 = 전부 회색 단색(SLA/FDM 출력) |
| 촬영 방식 | 부품을 **3그룹**으로 나눠 빈에 무작위 적재 후 촬영 |
| 자세 | 그룹 내 부품을 무작위 배치(겹침 ~60% + 펼침 ~40%) |

### 그룹 구성 (각 그룹 9종)

| 그룹 | shot 범위 | 장수 | 부품 |
|------|-----------|------|------|
| **g1** | shot_001~034 | 34 | 9종 |
| **g2** | shot_035~067 | 33 | 9종 |
| **g3** | shot_068~100 | 33 | 9종 |

- **그룹 배치는 무작위**(임의 선택). 그룹별 부품 목록·category_id는 첨부 `real_capture100_group_labels.json` 참조.
- 각 장에는 **해당 그룹의 9종 중에서만** 부품이 등장합니다(다른 그룹 부품 없음). → 라벨 검증 시 그룹 밖 부품이 나오면 오류로 탐지 가능.

---

## 3. 라벨링 (instance)

- 도구 = **labelme 6.3.1** + SAM2/AI-Box(박스 치면 외곽 자동 분할).
- 각 부품마다 polygon 1개, `label` = STL 이름(예: `main_body`, `bracket_case`).
- **occlusion 처리**: 보이는 부분만 라벨링(가려진 뒤쪽은 상상해서 그리지 않음).
- **6DoF pose 없음**: 실물 자세를 실측하지 않아 pose GT는 없습니다. → 실증 평가는 **class / mask / box / CAD 식별**까지.

### ⚠️ 라벨링 주의 1건 (미리 공유)
- `guide_paper_roll_cover_left` ↔ `guide_paper_roll_cover_right`는 **거울쌍**이라 depth만으로 좌/우 구분이 사실상 불가합니다. 라벨링 시 둘을 **다르게만** 배정했고(순서가 뒤바뀌었을 수 있음), 빈피킹 실용상 동급으로 봅니다. 평가 시 이 두 클래스는 **묶어서(혹은 관대하게)** 보는 걸 권합니다.

## 4. 폴더 구조 (6000 서버 기준)

```
/data/jtm/synth_out/real_capture100/
├── npy/            (100) 원본 depth. 848×480 uint16, mm.   ← raw 원천
├── png/            (100) 원본 시각화(turbo). 확인용.
├── label_png/      (100) 라벨링용 PNG. 1696×960 (= npy ×2).
├── labelme_json/   (100) 라벨링 결과. polygon 좌표는 1696×960 기준.
└── synthformat/    변환 결과 npz (합성 dataset_2denc 포맷과 동일).  ★ 학습/평가는 이걸 사용
```

> **좌표 스케일 주의**: `label_png`(1696×960)는 `npy`(848×480)의 **2배**입니다. labelme polygon 좌표는 변환기가 **÷2** 해서 npy 해상도로 매핑합니다.

## 5. 변환 포맷 (`synthformat/*.npz`)

합성 `dataset_2denc/npz/` 와 **동일 키**로 맞췄습니다.

| 키 | 내용 |
|----|------|
| `depth` | **512×512 float32**, 단위 **meter**, 배경 = **NaN**, 부품 픽셀만 유효 |
| `inst_id` | 512×512 int32. 부품별 1,2,3… (0 = 배경) |
| `category_id` | 512×512 int32. **1~27** (합성과 동일 번호, 배경 0) |
| `meta` | JSON 문자열. shot/group/instances(부품별 category_id·stl)/orig_shape 등 |

- `category_id` **1~27은 합성 데이터와 완전히 동일한 번호**입니다(`--label_offset 1` 그대로 사용 가능).
- depth는 **부품 픽셀만** 값이 있고 나머지는 NaN(합성의 배경 NaN과 동일 처리).

## 6. ⚠️ 컨펌 요청 (변환 CONFIG 3항목)

아래 3개는 **합성 데이터와 동일하다고 가정**하고 변환했습니다. 혹시 코드가 기대하는 값과 다르면 알려주세요 — 변환기 CONFIG **한 곳만 수정**하면 **1분 내 재변환**됩니다(라벨링 결과는 재사용, 수작업 안 날아감).

| 항목 | 우리 가정값 | 확인 요청 |
|------|-----------|-----------|
| `TARGET_RES` | **512** | 합성과 동일 512 맞는지 |
| `DEPTH_UNIT` | **meter** (mm ÷ 1000) | detector 입력 단위가 m 맞는지 |
| `BG_VALUE` | **NaN** | 배경 표기가 NaN 맞는지 (0/−1 아님) |

### 추가 협의 1건 — 해상도 변환 방식
- 원본은 **848×480(aspect 16:9)**, 합성/타깃은 **512×512(1:1)** 로 aspect가 다릅니다.
- 현재는 **nearest resize**로 512×512에 맞췄습니다(라벨 섞임 방지 위해 보간 안 씀).
- **crop / pad / 종횡비 유지** 중 조교님 코드가 기대하는 방식이 있으면 알려주세요. 변환기에서 대응하겠습니다.
