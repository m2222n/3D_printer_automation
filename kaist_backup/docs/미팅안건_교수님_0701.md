# 7/1 미팅 안건 (교수님 포함) — 합성↔실측 정합성 + 남은 기간 계획

> 팀6 · 2026-07-01 12:30
> 목적: (1) 합성 학습데이터와 실측 데이터의 **depth 값 범위/스케일 불일치** 해결 방향, (2) 학습 전 **단일 부품 정합성 검증** 설계, (3) 7/9까지 **일자별 계획**, (4) 최종 산출 = **정량·정성 평가**.

## 1. 문제 제기 — 합성과 실측의 depth 분포가 크게 다르다 (숫자 확인됨)

우리 데이터로 직접 측정한 값:

| | 합성 (dataset_2denc) | 실측 (real_capture100) |
|---|---|---|
| 단위 | meter | mm (raw) |
| 부품 depth **중앙값 분포** | **0.34 ~ 0.43 m** | **0.7 ~ 3.2 m** |
| 부품 depth 전체 min~max | ~0.35 ~ 0.40 m | 0.66 ~ 4.30 m |
| 특징 | **~40cm 한 점에 몰림** (촘촘·일정) | **0.7~3.2m로 넓게 흩어짐** |

**핵심**: 두 분포가 **거의 겹치지 않는다.** 합성은 카메라~부품 거리를 좁게(≈40cm) 고정해 촘촘히 찍었고, 실측은 실제 빈 높이·촬영 거리 때문에 훨씬 멀고 넓게 퍼져 있음.

→ 이 상태로 학습된 detector에 실측을 넣으면, **입력 depth 값 자체가 학습 분포 밖(out-of-distribution)** 이라 정상 동작을 기대하기 어렵다.

### 무엇이 다를 수 있나 (교수님 지적 정리)
1. **Depth 값의 절대 범위** — 합성 ~0.4m vs 실측 0.7~3.2m
2. **부품 크기(픽셀상 스케일)** — 거리가 다르면 같은 부품도 화면에서 크기가 달라짐
3. **normalize 기준** — 어떤 범위를 [0,1] 등으로 정규화하느냐가 두 도메인에서 어긋남

## 2. 여쭤볼 것 — normalize 범위 불일치를 어떻게 해결?

### 🔵 조교님 최종 답 (7/1 톡방) — 방향 확정됨
> **"배경 싹 다 0으로 바꾼 다음에 Normalization 0-1로 스케일링해서 하면 된다."**
> **"(그림) 배경에 object가 섞여서 메인 부분이 almost 0로 나온 것 → 저 배경 부분을 다 0으로 바꾸고 진행하라."**
> **"각 이미지별 레이블 데이터 확보했죠? evaluation 하려면 각 부품 위치·종류를 알아야 한다."**
> **"학습 시 경계를 뭉개는 augmentation이 필요해 보인다 — 내가 고민 후 공유하겠다."**

**왜 배경 0인가 (그림으로 확인된 근본 이유)**:
- 실측에는 빈 벽/주변 물체가 **가까운 depth(그림 왼쪽 빨강 띠)**로 잡힘. 이게 섞인 채 **0-1 정규화하면 배경이 min/max를 잡아먹어** 정작 부품이 0 근처로 눌림(그림의 어두운 파랑 = 부품이 눌린 상태, `all_valid=3%`).
- **해결**: 배경을 전부 **0**으로 밀어 제거 → **부품 픽셀만 남기고 0-1 스케일링**. ✅ 우리 **labelme mask가 여기서 결정적** — mask 밖 전부 0으로 밀면 배경 띠가 깨끗이 제거됨.

**우리 조치 (확정)**:
1. 변환기 **`BG_VALUE = NaN → 0`** 으로 변경. (부품 mask 밖 전부 0)
2. depth **0-1 정규화 추가** — 부품 픽셀만 min-max로 [0,1] 스케일링(배경 0 유지).
3. ✅ **레이블 = 이미 확보 완료** (labelme 100장 instance mask + category_id 1~27). → 조교 evaluation 요건 충족.
4. **경계 뭉개기 augmentation = 조교 담당, 학습 측에서 처리 → 대기.** (우리 데이터 변환과 별개)

**→ 미팅에서 짧게 확인**: 0-1 스케일링 기준을 **per-scene min-max** vs **데이터셋 고정 상한** 중 무엇으로 할지(합성도 동일 기준이어야 정합).

### 우리가 준비했던 후보 방향 (조교 답과 대조용 — 참고)

- **(A) 상대 depth로 통일** — 절대 거리 대신 "부품 표면 기준 상대 depth"(예: 장면 median 빼기 / min-max per-scene)로 정규화 → 카메라 거리에 불변. **가장 유력하다고 봄.**
- **(B) 합성 생성 거리를 실측에 맞춤** — 합성 카메라를 실측 분포(0.7~3.2m)로 재생성. 단, 재렌더 시간 소요.
- **(C) 실측을 합성 거리대로 리스케일** — 실측 depth를 합성 범위로 선형 사상. 물리적 왜곡 우려.
- **(D) depth → point cloud 역투영 후 정규화** — 6/25 발표 Q&A의 "modality 통일"과 연결. 카메라 K로 역투영하면 스케일이 물리 단위로 통일됨.

→ **질문**: detector 입력 정규화(`--input_mode zv` = 정규화 depth + valid mask)가 어떤 기준으로 normalize하는지에 따라 답이 갈림. **어떤 방식이 합성↔실측 갭을 최소화하나?**

## 3. 학습 전 검증 단계 — 단일 부품 정합성 확인 (교수님 제안)

> **"학습을 하기 전에, 부품 하나만 대상으로 정합성을 먼저 확인하자."**

### 설계
1. **부품 1종 선택** (형상이 뚜렷한 것, 예: `main_body`).
2. **합성 = 촘촘하게**: 그 부품 하나를 **모든 간격·거리·각도**로 가상 렌더 (거리 스윕 포함).
3. **실측 = 한 장**: 같은 부품을 Blaze로 1장 촬영.
4. **매칭 확인**: 실측 1장이 촘촘한 합성 세트 중 **하나라도 매칭되는가? 얼마나 잘 되는가?**
   - **정량**: depth 히스토그램/통계 비교, nearest 합성 프레임과의 거리(예: depth L2, 형상 IoU), CAD codebook 매칭 점수.
   - **정성**: depth 시각화 나란히 비교, 매칭된 합성 프레임 오버레이.

### 의도 (교수님 말씀 그대로)
- 실측에서 뽑히는 **depth 값의 범위**가 합성과 다른지
- **부품 크기**가 다른지
- → **실측 depth ↔ 합성 depth 의 데이터 정합성**을 학습 전에 확인 (전체 파이프라인 돌리기 전 리스크 조기 발견)

## 5. 최종 산출물 (7/9 목표)

- **정량 평가**: 실측 test에서 recall / class acc / CAD 식별 / mask IoU / box (합성 test와 비교). + 합성↔실측 **도메인 갭** 수치.
- **정성 평가**: 실측 예측 시각화(성공/실패 케이스), 단일 부품 정합성 오버레이, depth 분포 before/after 정규화.
