## 🚨 핵심 발견 — 실측 depth 절대값에 약 3.5배 고정 스케일 오류 (데이터는 살아있음)

**실제 부품 거리 = 팔 뻗은 정도 ≈ 0.8~1.0m (태민님 확인 + CAD 역산 일치). 저장 depth = 2.8~3.1m → 약 3.5배 부풀려짐.**

### 두 독립 방법으로 배율 교차검증
| 방법 | 결과 |
|------|------|
| CAD 실제 크기(canonical_bbox_mm) ↔ 화면 픽셀 크기로 거리 역산 | 부품 실제 거리 **≈ 0.8~1.0m** (700~1200mm 분포) |
| 저장된 부품 depth (median) | **2.8~3.1m** |
| **→ 저장 depth / 실제 거리 배율** | **≈ 3.5배** (분산 0.48, 거의 고정) |

- 초점거리 f≈641px(HFOV 67°, W=848) 가정. `scripts/probe_sim2real_matching.py` 역산 로직.
- ⭐ **CAD 역산 거리(0.8~1m)가 태민님 체감 "팔 뻗은 정도"와 정확히 일치** → 기하학적으로 부품 실제 거리는 0.8~1m가 맞음. 0.5m 아님.
- 그런데 저장 depth는 2.8m → **별개의 약 3.5배 스케일 오류가 확실히 존재**.
- labelme로 사람이 직접 그린 부품 영역의 depth가 2.8m → 배경 혼입 아님, **부품 자체가 3.5배로 측정됨**.

### ✅ 왜 데이터는 살아있나 (재촬영 불필요)
1. 배율이 **거의 고정(~3.5배)** → 나눗셈 한 번으로 원값 복원 가능.
2. 조교 파이프라인은 **어차피 median 빼고 robust scale 정규화** → 고정 배율은 정규화에서 상당 부분 자동 상쇄. **보정 없이도 평가 가능성 있음**(다음 검증 항목).
3. **라벨링 100장(픽셀↔부품)은 스케일과 완전 무관 → 100% 그대로 유효.** 진짜 자산은 안 죽음.

### 의심 원인 (촬영 스크립트 `blaze_capture_100.py`)
- Blaze를 `Coord3D_C16`/`Mono16` + `OperatingMode=ShortRange`로 열려 시도하나, 노드 설정이 **실패해도 조용히 넘어가는 구조**(`_try`, try/except) → ShortRange가 실제로 안 걸렸을 수 있음.
- Blaze는 `Scan3dCoordinateScale`(raw→mm 스케일)이 있는데, pypylon `res.Array`가 스케일 적용 전/후 어느 값을 주는지 미검증. **5.26배 = 스케일 미적용 의심**.

## 📊 정규화 후 비교 (조교 파이프라인 `robust_normalize_depth` 통과)

| | RAW depth (m) | 정규화 median | 정규화 p05~p95 | std |
|---|---|---|---|---|
| 실측 main_body | 3.09 (3.01~3.20) | 0.0 | −0.45 ~ +0.55 | 0.32 |
| 합성 main_body | 0.40 (0.40~0.40) | 0.0 | 0.0 ~ +1.0 | 0.33 |

- **std(퍼짐)는 비슷(0.32/0.33)** → median-subtract 정규화가 절대 거리 갭 자체는 흡수.
- 그러나 **정성 시각화([probe_main_body.png](probe_main_body.png))에서 형상 패턴이 완전히 다름**:
  - 합성: CAD 격자·구멍 날카로움, 표면 depth 변화폭 **5mm**(거의 평면 — 0.4m 근접 촬영)
  - 실측: 부드러운 입체 곡면, depth 변화폭 **150~300mm**(3m 원거리 + 스케일 왜곡)
- 부품 픽셀 크기도 실측 300~480px(작음) vs 합성 큼.

→ **정규화로 median은 맞춰지나, "부품 형상 프로파일" 자체가 안 맞음.** 근본 원인 = 위 depth 값 신뢰 문제.

## 🧭 방향 추천 (태민님 "방향 추천해줘") — 재촬영 불필요, 기존 데이터로 진행

### 1순위 (즉시, 카메라 없이) — 정규화가 배율을 흡수하는지 증명
- 실측 depth를 그대로 조교 파이프라인(`robust_normalize_depth` median-subtract)에 넣어 → **고정 배율이 상쇄되는지** 정량 확인.
- 흡수되면 **스케일 보정조차 불필요** → 100장 변환·평가 바로 진행. 안 되면 ÷3.5 보정 1줄 추가.

### 2순위 (카메라 없이, 내가 바로) — 합성 생성 거리 재정렬
- 현재 합성 cam_h=0.4m 고정 → 실측 실제 거리(**≈0.8~1.0m**, CAD 역산)와 정합되게 **카메라 거리 다양화(0.4~1.0m 스윕) 재생성**.
- 부품이 "평면"이 아니라 "입체 곡면"으로 찍히도록 = 실측 형상 프로파일과 정합.

### 3순위 (위 통과 후) — 100장 변환 + detector 평가
- 실측 → synthformat 변환(배경 mask, 배율 상쇄/보정) → 조교 파이프라인 평가(recall/class/mask 정량).

### 보조 (카메라 접속 가능할 때, 급하지 않음) — 스케일 원인 확정
- Blaze 재연결해 `Scan3dCoordinateScale`/`Scan3dCoordinateOffset`/`OperatingMode` 노드 확인 → 3.5배 근원 못박기. 촬영 스크립트 `blaze_capture_100.py`가 이 노드들을 "실패해도 조용히 넘어가게" 설정한 게 유력 원인.
- 조교님께 현상 공유(depth 절대값 3.5배 이슈) → 향후 촬영 스크립트 수정.

**결론: 재촬영 안 함. 고생한 100장 + 라벨링 전부 살아있음.** 고정 배율은 나눗셈/정규화로 처리. 다음주 금요일 미팅의 핵심 발견이자 안건 = "depth 절대값 3.5배 스케일 이슈 + CAD 역산으로 실거리 0.8~1m 확인 + 정규화로 흡수".
