## 2. 실증 데이터셋 공유 (7/1, 조교) — `real_capture100`

Blaze depth **실물 100장** + instance 라벨링 완료본을 조교에게 넘긴 문서.

| 항목 | 값 |
|---|---|
| 카메라 | Basler **Blaze**(ToF), top-down |
| 원본 | **848×480 uint16**, 단위 mm |
| 장수 | 100장 · 부품 **27종**(합성과 동일 category_id) · 전부 회색 단색 |
| 그룹 | g1 shot_001~034 / g2 ~067 / g3 ~100 (**각 9종**, 그룹 밖 부품 없음) |
| 라벨 | labelme + SAM2/AI-Box, polygon 1개/부품, occlusion은 **보이는 부분만** |
| 없는 것 | **6DoF pose GT 없음**(실물 자세 미실측) → 평가는 class/mask/box/CAD까지 |

⭐ **그룹 설계의 이점** = 각 장에 그 그룹 9종만 나오므로 **그룹 밖 부품이 라벨되면 오류로
자동 탐지**된다. 📌 이 발상이 **8/18 본촬영의 `group_labels_0818.json` 정답지로 이어졌다.**

🚨 **이때 이미 경고했던 것 — 거울쌍**
> *"`guide_paper_roll_cover_left` ↔ `right`는 거울쌍이라 depth만으로 좌/우 구분이 사실상
> 불가. 라벨링 시 둘을 다르게만 배정했고(순서가 뒤바뀌었을 수 있음), 빈피킹 실용상
> 동급으로 본다. 평가 시 두 클래스는 묶어서(혹은 관대하게) 보는 걸 권한다."*

⇒ ⭐⭐ **8/19 F1 측정에서 이 쌍이 실제로 6회 혼동됐다.** 7/1에 예고된 문제가 그대로
재현된 것이고, 같은 논리로 `13_variant`↔`14_13`에 **평가기 동치 처리**를 넣었다.
⚠️ 단 `roll_cover` 쌍은 **아직 동치 처리하지 않았다** — 두께 6mm 차가 있어
"원리적 불가"인지 확정하지 못했다(8/18 판정 = 경계선).

## 3. 교수님 미팅 안건 (7/1) — 합성↔실측 정합성

**문제 제기 = 두 분포가 거의 겹치지 않는다**

| | 합성 (dataset_2denc) | 실측 (real_capture100) |
|---|---|---|
| 단위 | meter | mm (raw) |
| 부품 depth 중앙값 | **0.34~0.43 m** (≈40cm 한 점에 몰림) | **0.7~3.2 m** (넓게 흩어짐) |

→ 학습 분포 밖(out-of-distribution) 입력이라 정상 동작을 기대할 수 없다.

### 🔵 조교 답 (7/1) — 방향 확정
> *"배경 싹 다 0으로 바꾼 다음에 Normalization 0-1로 스케일링해서 하면 된다."*
> *"배경에 object가 섞여서 메인 부분이 almost 0으로 나온 것."*
> *"학습 시 경계를 뭉개는 augmentation이 필요해 보인다."*

**왜 배경 0인가** — 실측에는 빈 벽/주변 물체가 가까운 depth로 잡히는데, 이게 섞인 채
0-1 정규화하면 **배경이 min/max를 잡아먹어 정작 부품이 0 근처로 눌린다**
(`all_valid=3%`). ⭐ **labelme mask가 여기서 결정적** — mask 밖을 전부 0으로 밀면 해결.

⇒ 📌 **이 원리가 회사 빈피킹의 "빈·배경재 선정"으로 이어졌다** — 8/18에 골판지 빈이
5/5 통과한 것도 **바닥이 850nm를 흡수해 배경이 depth상 사라지기 때문**이다.
(다만 8/18에 *"유효율은 높다/낮다가 아니라 학습 때와 같은 화면 구성인가의 대리 지표"*로
더 정확히 정리됐다.)

### 🚨 교수님 지시로 발견한 것 — 실측 depth에 약 3.5배 스케일 오류
*"학습 전에 단일 부품 정합성부터 검증하라"* → `main_body` 하나를 합성 vs 실측 직접 비교
→ **실측 저장값 2.8~3.1m인데 CAD 역산 실제 거리는 0.8~1.0m**.

⭐ **재촬영 불필요로 판정** = 고정 배율이라 정규화가 흡수하고 라벨링 100장도 스케일 무관.
🚨 **이것이 depth 단위 버그 계열의 시작이었다** — 이후 7/29~8/5에 **닷새에 다섯 번**
같은 유형을 밟았고, 결국 `depth_units.py` 단일 출처로 정리됐다
(정답: `depth_m = raw × 10 / 65535`).

## 4. 미팅 공유자료 (7/3) — sim2real 붕괴와 진범 규명

**30초 요약(당시 원문)**
- 합성 학습 모델을 실측 100장에 처음 적용 → **검출은 완벽(recall 1.0)한데 식별이
  80% → 5%로 붕괴** = 전형적 sim2real 갭이 하필 프로젝트 핵심 KPI에서 터짐
- 재학습 실험 3종으로 원인 규명 → **진범 = 스케일(카메라 거리) 갭.**
  cam_h 스윕 재학습으로 **실측 5% → 39.6%(약 8배)** 회복
- 노이즈 aug 단독은 13.6%로 미미했고 **합성 성능까지 깎았다**

⭐⭐ **여기서 확립된 패턴이 회사 개발에도 그대로 유효하다**
= **"검출(위치)은 되는데 식별(종류)이 무너진다"**. 8/5 cross-session에서도, 8/19
90장에서도 **위치 precision 0.97 / 종류 50%대**로 같은 형태였다.

⭐ 조교 피드백 4건 처리 = ①배경 0 ✅ ②부품만 0-1 정규화 ✅ ③evaluation 라벨 확보 ✅
④경계 뭉개는 aug = 조교 담당(→ 이것이 나중에 **csblur**가 되어 최종 모델 T100의 init이 됨)
