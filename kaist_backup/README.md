## 문제 정의

박스(빈) 안에 여러 종류(27종)의 부품이 겹쳐 쌓여 있을 때, **각 부품이 어디에 있고 어느 부품인지**를 Depth 카메라만으로 인식해 로봇이 집을 수 있게 한다. 세 가지가 특징이자 도전이다.

1. **인스턴스 세그멘테이션 + 종류 식별** — Depth 맵에서 개별 부품 마스크를 분리하고, 27종 CAD 중 무엇인지까지 식별.
2. **ToF Depth Map 단독** — 색·질감 없이 거리(깊이)만으로 인식(RGB 미사용). 조명 변화에 강하고 형상을 직접 얻어 로봇 파지 좌표 계산에 유리한 대신, 색 기반 미세 패턴 구분은 불리하다.
3. **합성→실측 전환(Sim2Real)** — 실측 라벨이 적어 CAD로 합성 데이터를 대량 생성하되, **실제 환경에서 성능을 유지하는 것**이 핵심 과제(도메인 갭 축소).

### 핵심 강점 — 데이터를 모으지 않아도 되는 인식 모델

- **데이터 수집·라벨링 최소화** — CAD만 있으면 합성으로 학습 데이터와 정답(GT)이 자동 생성된다. 신규 부품 추가도 쉽다.
- **Depth-only** — 색·조명 등 외부 환경에 강건. 회색 단색 부품도 형상으로 구분된다.
- **CAD 연계** — 검출에서 끝나지 않고 '어느 CAD 부품인지'까지 식별해, 로봇이 부품별로 다르게 집는 단계로 바로 이어진다.

> 1차 발표(6/9) 피드백으로 방향이 수렴했다: RGB→**Depth만**, 분류→**검출+분할+CAD 식별**, 실촬영→**합성 데이터(GT 자동)**, 제로샷→**사전 정의 부품 지도학습 먼저**.

## 모델 구조 — 두 인코더 + 하나의 검출기

```
① 오프라인 — CAD 형상 사전 구축
   CAD STL(27종) → Point Cloud → 3D CAD Encoder (PointNet++)
                 → CAD Memory Bank (27종 × 256-d 형상 임베딩 codebook, frozen)

② 추론 — Depth 한 장
   Depth 맵(320×576) → 2D Depth Detector (DETR / Mask2Former 계열, query 100)
                 → box(위치) / mask(분할) / class(1..27) / CAD VQ(어느 CAD)
                   └ CAD VQ = 쿼리 임베딩을 frozen codebook과 정렬(cad_align)·분류(cad_ce)
```

- **3D CAD Encoder ([PointNet++](https://arxiv.org/abs/1706.02413))** — CAD를 점으로 뿌려 계층적 set abstraction으로 국소→전역 형상을 학습, 부품마다 형상 임베딩을 만들어 codebook에 저장.
- **2D Depth Detector (DETR/[Mask2Former](https://arxiv.org/abs/2112.01527) 계열)** — Depth 한 장 입력. CNN+FPN → Transformer object query decoder → 4개 헤드(class/box/mask/CAD VQ). 추론 입력은 오직 Depth이며, 실제 카메라 한 대로 배포하는 상황과 동일하다.
- **CAD codebook 매칭** — [VQ-VAE](https://arxiv.org/abs/1711.00937)의 codebook 개념을 차용해 '도면을 아는' 제조현장 특성을 활용한다.
- **2단계 학습** — ① 검출(class+box+mask) 안정화(warmup) → ② CAD codebook 정렬(joint) 추가. Hungarian 매칭.

## 합성데이터 파이프라인 (`synth/`)

CAD(STL) 27부품을 가상 빈에 **중력으로 낙하·적재**시켜 장면을 만들고, **Depth / Segmentation / 6DoF pose 라벨을 자동 생성**한다.

> 원본 CAD는 28종이었으나, 1종(`10_guide_paper_roll_l`, 약 236mm)은 보유 3D 프린터 빌드볼륨을 초과해 실물 출력이 불가능하여 제외했다. 학습·합성데이터 대상은 **27종**이다.

- **렌더러**: 초기 [BlenderProc](https://github.com/DLR-RM/BlenderProc)(물리 렌더) → **렌더 속도 문제로 point-splat 전환**. CAD 표면을 point cloud로 샘플링 → 카메라 시점 투영 → 각 점을 원반처럼 splat해 Depth 맵 생성. 색이 아니라 Depth만 필요하므로 이 방식으로 충분하며, 학습 중 실시간 대량 생성이 가능하다.
- 부품은 **회색 단색** 고정 — 색이 다양하면 모델이 형태가 아니라 색으로 판별할 위험이 있어서다.
- 계보: BlenderProc (Denninger 2019, BOP 표준) · Domain Randomization (Tobin 2017).

### `synth/` 주요 파일

| 파일 | 역할 |
|------|------|
| `gen_one.py` ~ `gen_one_v3.py` + `run_batch*.sh` | 버전별 1 scene 단위 생성(상태 누수 회피) + 배치 |
| `gen_one_2denc.py` | 모델 학습용 데이터 생성기 (depth + 인스턴스 마스크 + class + 자세 메타) |
| `gen_one_2denc_camsweep.py` / `_camnear.py` / `_camfit.py` | 실측 촬영 거리에 맞춘 카메라 높이 정합 생성기 (스케일 정합 실험) |
| `edge_blur_aug.py` | 엣지 블러 augmentation (합성 경계를 실측 ToF 특성에 정합) |
| `depth_noise.py` | ToF depth 노이즈 모델 (거리비례 Gaussian + dropout + flying pixel) |
| `probe_3d_coords.py` | CAD에서 3D 좌표(키포인트·주축·grasp 등) 추출 |

## Sim2Real 실험 (`experiments/`) ★ 프로젝트 핵심

합성으로만 학습한 모델을 실측 Depth로 동작시키기까지의 전 과정 스크립트(팀 6 작성). 발표 결과를 낸 재현 경로는 `experiments/README.md` 참고.

### F1 0.05 → 0.684, 여섯 번의 방향 전환

| # | 시도 | 실측 F1 | 배운 것 |
|---|------|:---:|------|
| 1 | 합성만 학습 → 실측 평가 | 0.05 | Sim2Real 갭 발견 — 종류 인식이 붕괴 |
| 2 | 스케일 원인 규명 → 카메라 높이 스윕 | 0.396 | 진범 = 부품 픽셀 크기 정합 (8배↑) |
| 3 | 합성 augmentation 요인분리 6판 | 0.203 | 엣지블러 1mm만 baseline 초과 — 나머지는 무효·역효과 (음성 결과) |
| 4 | **전략 대전환 = 실측 fine-tune** | 0.45 | 합성 다듬기보다 실측 소량이 핵심 요인 |
| 5 | **실측 200장 + 학습률 스윕** | 0.82 | 학습률 1e-4가 결정타 (test40 0.63→0.82) |
| 6 | 정식 조건(test100) 재평가 | **0.684** | 조교 피드백(train:val:test 4:1:5) — 엄격한 시험지 |

> **핵심 교훈**: 데이터를 더 그럴싸하게 만드는 것보다, **소량이라도 실측으로 fine-tune** 하는 것이 sim2real 전환의 진짜 핵심 요인이었다. 실패한 방향(합성 augmentation 강화)을 데이터로 배제한 것이 성공 방향을 찾은 근거가 됐다.

### 평가 지표

**F1-Score (micro)** — 검출 + 종류 정답 + 마스크 IoU ≥ 0.5 를 모두 만족해야 TP(과잉예측 페널티 포함). 목표 F1 = 0.7. `model/eval_depth_vq_detector.py` (+ `_nms.py`)가 `--score_thresh` / `--iou_thresh`로 F1·precision·recall 산출.

## 최종 결과

### 성능 (실측)

| 설정 | F1 | 위치 F1 | 종류 정확도 |
|------|:---:|:---:|:---:|
| 합성만 (fine-tune 전) | 0.203 | — | — |
| **최종 모델 (27종, test100)** | **0.684** | **0.88** | **0.85** |
| (참고) test40 소규모 조건 | 0.818 | 0.91 | 0.87 |

- **위치·검출은 로봇이 집을 수 있는 현장 수준(0.88–0.91)에 도달** — 부품을 다 찾고 마스크도 정확.
- **종류 식별 0.85** — 이미 높으며, 남은 개선 여지는 대칭·유사 부품 구분에 집중된다.

### 병목 규명 — 종류 혼동의 3가지 원인 (처방이 각각 다르다)

| 유형 | 예 | 차이의 본질 | 처방 |
|------|-----|------------|------|
| **A** 거울상·축대칭 + 크기 미세차 | 롤커버 좌/우 | Depth 구분 원리상 어려움 | 클래스 병합 |
| **B** 표면 구멍·슬롯 패턴 차이 | 브래킷 유사쌍 | 평면 내 얕은 패턴, 깊이차 거의 없음 | RGB 융합 |
| **C** 입체 돌기 미세차 | 소형 브래킷 변형 | 가능하나 해상도·포즈 한계 | 고해상 depth + 포즈 |

> **엄밀함**: "대칭이라 병합"을 남발하지 않았다. 4쌍 중 CAD 기하를 하나씩 검토해 원리상 구분 불가능한 **롤커버 1쌍만** 병합했고, 그마저 재학습 결과 F1 0.669로 27종(0.684)을 넘지 못해 — **병목이 학습이 아닌 센서(Depth) 물리 특성**임을 재확인했다.
